# 全NPCの一括出力

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

「出力 → 配置付きNPCコードを全件出力…」で配置のみNPC・会話NPC・通常shopをTXTまたは根拠付きJSONへ保存する。
会話・コードの統合チェックONでは会話を統合し、OFFでは各観測を別ブロックで残す。
NPC一覧の表示フィルターに隠れた個体も対象。同じ観測配置は1つにまとめる。

初期化のみのNPCは本文に`end;`を置き、その後に`OnInit:`を出力する。
会話がある場合は既存の`close;`等で終了するため余分な`end;`を追加しない。
会話未観測の場合も処理や初期化値を補完しない。初期化もない空NPCはclassを問わず1行で出力する。
初期化は配置ごとに1つとし、観測値の矛盾は確認用ブロックで保持する。
groupが0以下、titleが空文字・空白だけの場合は命令を表示しない。両方省略され、職業外見・waitingroom等の初期化もなければOnInitを生成しない。
元の値と根拠は観測JSONへ保持する。NPC定義間と、callshop用別shop定義との間には空行を入れる。

統合対象外の会話も個別候補として保持する。配置が不正・不足する記録は除外理由とともに
JSONへ残す。同名で配置が異なる候補は自動改名・選択せず、TXTではコメントとして残す。
会話なしshopはNPC種shopの配置定義とし、同じNPCの空会話scriptは重複生成しない。
会話ありshopは観測した遷移位置へcallshopを生成し、商品定義は別の非配置shopとして同じファイルへ含める。
統合チェックONでは対応商品を維持して会話を統合、OFFでは個別の観測ブロックを残す。
商品IDはクライアント観測値の編集用候補で、DB対応は未照合と明記する。個別の確認済みshop出力も引き続き使用できる。
対応未解決のshopは除外理由と元レコードを保持し、同一配置の異なるshop内容やNPC形式の競合は全体をコメント化する。
初回HIDDEN/CLOAKEDの通常shopは既存の制約どおり確認用コメントとする。手動確認したタイマー設定は専用の出力を使用する。
未観測の条件や元スクリプトの処理は補完しない。

保存先選択前に観測内容をコピーする。最大64MiB、元ログ・選択中の長さ定義・config以下への
上書きを拒否し、一時ファイルから置換する。

以下は各段階での過去の検証記録。v0.0.4全体の結果は[スナップショット記録](../releases/v0.0.4.md)を参照。

全321テスト通過。20261028-012526-0abe69d9では両モードで141配置を出力し、配置検証により
除外した12観測記録をJSONに保持した。Auriga本体での実行確認は未実施。
全件shop対応後は全399テスト通過。同ログの新出力では141配置・OnInitなしを確認した。
20261027-175743-38a7ccc0でもshop観測5件を両モードへ取り込み、shop取込みエラーなしを確認。
配置等の除外記録は出力JSONと末尾コメントに残す。全件出力でも未取得の配置値は補完しない。

選択肢ごとに商品一覧が異なるcallshopは、それぞれの観測した商品定義へ結び付ける。
商品一覧が異なる応答は同一応答としてまとめない。同一の選択肢・会話経路で商品内容が
変わる場合も、条件を推測せずインデント付きの無条件ブロックで両方の候補を残す。
この併記は編集用であり、商品切替条件の復元を意味しない。

競合により確認用コメントとなったNPCは、JSONの全体aurigaとentries内の
NPC別aurigaにも同じコメント化済みコードを保存する。review_only表示と
実際のコードを一致させ、元の商品一覧や対応根拠はshops等へ保持する。

初回HIDDEN／CLOAKEDまたは両ビット併存の通常shopは、コメント化済みの
コードを保持し、JSONのreview_onlyとGUIの要確認件数にも反映する。
script(HIDDEN)／script2(CLOAKED)で表現できる会話付きcallshopは、この理由だけでは
確認用コメントにしない。

JSONのentries内のnpc要約には、配置コード生成に使った初回状態とその根拠を保存する。
最初の配置観測が初回状態未取得で、同じ配置の会話観測に初回状態がある場合も反映する。
entities／conversations内の元観測は変更せず、現在のoptionsと初回initial_optionsも区別する。
初回状態が矛盾する場合は、従来どおり確認用コメントと各観測の根拠を残す。

初回状態のoptionsが不正な型・範囲の場合は、その配置だけを除外する。
他の正常なNPCの出力は続行し、除外理由と元の個体・会話・shop観測をJSONへ残す。
不正値をvisibleへ置き換えたり、推測した状態で配置宣言を作ったりしない。

## 接触候補とwarp分類

class 139・111・844・45を接触候補の対象とする。会話のないワープ推定ではその他のclassも候補に含める。全処理がOnTouchとは断定しない。NPCを宛先とするmesから始まる観測は、
クリックSENDを捏造せず接触候補として保存し、同じ配置の会話と統合する。
生成は範囲付きscriptとOnTouchラベルを用い、mes等とwarpが分岐する場合もscriptを維持する。

接触範囲は各軸の最小値を1（3×3セル）とする。歩行パケットは完了通知ではなく、
移動先へ到達する前に接触し得るため、通知の始点・移動先から接触範囲を逆算しない。
歩行通知しかない場合・位置不明の場合は1,1を採用し、range_basisで根拠を区別する。
位置通知・位置補正による同MAPの位置がある場合は、その位置差を候補とし各軸最低1とする。
実際のサーバー設定や接触位置を確定したとは扱わない。歩行の元データは根拠として残す。
X・Yの軸根拠はconfirmed_axesとして独立に保持する。一方の軸だけ位置差の根拠がある場合は、
その値を対の軸にも仮採用する。各観測でX=3だけ、別の観測でY=2だけ得られた場合は、
統合後は3,2とし、先の仮採用値3がYの根拠2を上書きしないようにする。
両軸に根拠が揃う場合を除き、script・warpとも範囲の暫定コメントを付ける。
歩行通知や同一セルでの位置差0は軸の確定根拠にしない。


会話なしの移動は、同一capture・flow・直前MAP世代で、直近のプレイヤー移動先から
各軸15セル以内（仮最大31×31セル）のNPCを候補とする。
class 139→111→844→45→その他の順に優先し、その順位内でチェビシェフ距離が
最小の一意な候補を接触warp候補として保持する。同距離の複数候補、旧世代のみ、
位置不明では割り当てない。歩行通知の移動先による選択も推定であり、到達・起因の確定ではない。
解析JSONのdialogues.touch_warp_inferencesへ候補・距離・順位・選択／未確定理由を残す。
最大2000推定、1推定の候補詳細64件とし、切詰め・古い記録の脱落件数を明記する。
hideon／cloakonの個体は接触に反応しないため、近傍候補の選別時は現在のoptionsを確認し、
hide／cloak中の個体を除く。同一セルの複数個体でも適用する。初回状態は配置宣言用に保持し、
現在のhideoff／cloakoffによる再反応と混同しない。同順位・同距離の反応可能候補が残る場合は割り当てない。

warpだけの全経路が同じ移動先で、他の演出・資源・初期化を伴わない場合はwarp型配置とする。
異なる移動先やmes等があればscriptで各観測を残す。

インスタンス内のscript命令はgetmdmapnameを維持する。warp型の配置では関数式を
使わない仕様のため、MAP名を文字列で指定し、インスタンスであることだけを理由にコメント化しない。

生成時の名称正規化はreconstruction/instance_names.pyで扱う。例えば0k81@xm_d.gatから
3文字の生成識別子0k8を除き1@xm_d.gatとする。NPC名は、そのMAPの識別子と一致する
完全な_0k8が末尾にある場合だけ除く。_、_0、_0kで途切れた名前や異なる接尾辞は削らない。
本来の名前のアンダーバーと区別できないためで、欠けた名称も補完しない。
JSONのrendered_namesに生成名・観測名とnpc_suffix_statusを保存し、部分接尾辞の疑いは
ambiguous_partialで区別する。元のnpc・各観測・表示デコーダの生フィールドは変更しない。

会話・初期化のない配置のみNPCは、`map,x,y,dir<TAB>script<TAB>name<TAB>class,{}`の
1行とする。初回HIDDEN/CLOAKEDならその種別を保つ。形式はconfig/auriga/dialogue.jsonの
npc_empty、npc_touch_header、touch_label、warp_npc等で変更できる。

## 会話表示命令と固定保存（2026-10-30）

会話に関連付いたmessize/mespos/mesalignも、配置付き一括出力の統合ON/OFFとTXT/JSONへ含める。
表示設定に差がある観測は既存の会話統合規則で保持する。
大きな出力では保存開始時点の会話・出典・書式を固定し、別スレッドで生成する。
保存先選択中や生成中の会話更新・書式変更は、固定済み出力へ混在させない。

対象テスト3項目で、統合ON/OFFのTXT/JSON一致、モデル更新後の固定内容保持、
書式ファイルの再読込なしの生成、51会話のGUIバックグラウンド保存を確認した。
実ログ20261029-215033-0a6328faでは両統合設定で161配置・除外8件、messize3命令。
通常生成と固定生成はJSON全体で一致。除外が0件であることや、生成コードのAuriga実行を確認した結果ではない。
確認用の統合配置コードは同ログフォルダall-npcs-layout-generated-merged.txt、
件数・入力ハッシュ・出力ハッシュはnpc-layout-bundle-review.jsonへ保存した。
