# 配置付きAuriga NPC編集用ファイル

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

## 初回観測のHIDDEN／CLOAKED状態

同一取得・同一サーバーIP/PORT・ActorIDの初回NPC出現通知のoptionsを出現定義の基準とする。
initial_optionsとinitial_state_evidenceを保持し、hide/ cloakの状態更新・視界再観測・再接続では上書きしない。
取得セッションが変われば基準も分ける。サーバー不明時は接続内だけで保持する。
現状態のoptionsも別に保持し、NPC個体情報には現在値と初回値を表示する。

0x9FE／0x9FF／0x9FDのtype 6は通常NPC、type 12は歩行NPC種とする。
Aurigaの定義種別はtypeで分岐する: type 6は`script[(HIDDEN/CLOAKED)]`、type 12は`script2[(HIDDEN/CLOAKED)]`。
HIDDENビット0x2とCLOAKEDビット0x4は修飾子であり、scriptとscript2の選択には使わない。
rAthenaにはscript2種がないため、typeに関わらず`script[(HIDDEN/CLOAKED)]`とする。
両ビットが同時に立つ場合は単一状態に決めず、配置出力を停止して根拠を残す。
未取得状態は現在値から逆算しない。複数ログ間の初回状態不一致は自動採用せず、個別確認とする。
一括出力では不一致候補を全体コメントとして保持する。会話統合のON/OFF、初期化のみの保存にも対応する。

既知の歩行NPC（type 12）に対する再観測の0x9FDは、観測ログへ
`npcwalkto {to_x},{to_y},"{name}"; // {aid}: speed:{speed}` を出す（MARiA準拠）。
初回の0x9FDは出現登録の注釈のままとし、未登録の移動を命令化しない。

全362テスト通過。追加ログでは初回HIDDENが90観測区間、統合出力で38配置。
CLOAKEDは同ログにはなく合成データで検証。初回観測を出力基準とし、サーバー起動時の状態や状態変更原因は補完しない。

会話画面の「コード保存…」を開き「配置付きNPCファイルを保存…」を選ぶ。
「同一NPCの観測経路を統合」が有効なら選択NPCの統合本文、無効なら選択会話の本文を包んで出力する。
既存の「会話本文を保存…」は配置情報が足りない場合にも引き続き利用できる。

配置形式は次のとおり。値は会話に保持された観測時のNPC情報を使用する。

```text
map.gat,x,y,direction<TAB>script<TAB>NPC名<TAB>class_id,{
    // 従来の会話本文候補
}
```

実際の区切りはタブ。宣言・コメント・閉じ括弧は
`config/auriga/dialogue.json` の `npc_file_header` / `npc_file_footer` で変更できる。
古いプロファイルにこのキーがない場合は同梱の既定値を補う。
本文のインデントは既存indentを1段追加する。本文そのものの分岐・入力・矛盾処理は変更しない。

## 不足・不正な配置情報

マップ名・NPC名・XY・向き・外見クラスが全て必要。未観測値を0や仮名で補わない。
統合候補のマップが空のcapture_entityも、本文は生成できるが配置付き保存はできない。
統合を選んでいるのに統合対象がない場合も保存しない。

初期出力では、XYは0～1023、向きは0～7、クラスは0～65535の整数に限定する。
マップ名は32文字以下の英数字・アンダースコア・@・ピリオド・ハイフンに限定する。
NPC名はcp932で23バイト以下という保守的な出力制限を設ける。
これは全Auriga版の名前上限を保証するものではない。長い名前を自動切詰めしない。
タブ・改行・制御文字・宣言区切りやコメント記号・`::`等を含む名前は拒否する。
非対応名は根拠JSON・本文候補から手動で編集する。
元の観測ログと同じパスへの上書きも拒否する。

## 候補の意味と確認範囲

通常NPCはscript、歩行NPC種はscript2宣言による編集用候補。
起因・条件式・タッチ範囲・隠れた変数・タイマーは復元しない。
OnTouchや範囲の仮値は生成せず、npcwalkto以外の移動経路やクエスト制御を確定するものでもない。
未選択の分岐・不一致の無条件ブロック・演出不一致の注意は本文と同じように残る。
複数ブロックをそのまま実行したときの到達性まで、自動で元のサーバー処理に合わせることはしない。
候補を確認・編集し、NPC名の衝突や必要なマップ・外見IDを確認してから検証環境で利用する。

NPC配置のタブ区切りとクラスID＋本文の形式は
[Auriga公式リファレンス](https://github.com/auriga/auriga/blob/master/doc/script_ref.txt)と
[npc_parse_script実装](https://github.com/auriga/auriga/blob/master/src/map/npc.c)を照合した。
保存は既存コード出力と同じUTF-8。対象Auriga環境の文字コード設定に応じた変換は別途必要。
Auriga本体でのスクリプト読込・実行確認は未実施。

全219テスト通過。単一／統合本文の構造維持、配置不足・宣言への混入の拒否、旧書式互換、GUI保存を確認。
既存実ログでは旧会話のマップが未観測、新会話はNPC識別情報不足のため、配置付き生成の実例には使えない。
不足情報を埋めず、マップと配置を観測できた追加ログでの確認を次の実機課題とする。

歩行先と直後のMAP移動を根拠にしたOnTouch候補。会話本文はなく、warpだけを観測した。

歩行先の根拠Packet3415、MAP移動Packet3419（0始まり）。同一フロー・旧MAPで最高優先クラスの
最短距離候補が1体だったことをtouch_warp_inferencesに保持する。起因は確定しない。

統合ON/OFFの両方で、次の配置行が一致した。

```text
ev_season01.gat,27,91,0	warp	#warp_season01	1,1,prontera.gat,86,58
```

歩行先は到着確定ではないため、半径1/1の最小3×3セルを暫定採用する。両軸の確定根拠はない。
クリック開始の未観測フラグを消して完全な会話として扱わず、タイミング反復集計からも除外する。

mes等を含む場合のscript型、候補が複数の場合、視界外・別MAPの扱いは従来規則を維持する。
