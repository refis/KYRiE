# 同じメニューへの戻りをwhile候補にまとめる

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

同一会話の祖先メニューと、後で再び表示されたメニューの選択肢文字列・順序が一致し、
両方に選択応答がある場合、生成本文をwhile (1)内の1つのmenu/switchにまとめる。
同じ選択肢へ戻った箇所はcontinueに置き換え、終了を観測した応答はclose/end等を保持する。
AurigaRendererの共通処理なので、単一会話・統合会話・NPC配置付き出力で利用できる。

```text
while (1) {
    set '@menu,select("説明を聞く","終了");
    switch ('@menu) {
        case 1:
            mes "観測した説明";
            next;
            continue;
            break;
        case 2:
            close;
            break;
    }
    end;
}
```

これは観測した戻り経路を整理する編集用候補。元のコードがwhileだったことや、
別の周回・未観測の選択で同じ動作になることは確定しない。元変数・起因・条件式は生成しない。
continueの後のbreakは共通のcase書式によるもので、この経路では到達しない。

## まとめる範囲

メッセージ、nextへの応答、clear、cutin、エモーション・エフェクト・効果音を経た戻りを扱う。
同じ項目の応答は、戻り先で観測した別の項目の応答とともに1つのswitchへ整理する。
完全に同じ応答は共有し、異なる応答は従来のインデント付き無条件{}ブロックを保持する。
単一選択肢または全選択肢の完全同一応答に対するラベルなしmenuの規則も維持する。

以下を跨ぐ戻りは、この段階ではまとめない。

- 異なる選択肢または順序を持つ別メニュー。
- 数値・文字入力とその応答。
- 未応答のメニュー、マップ・ショップ遷移、終了・不明な境界。
- 戻り元と戻り先でcutinの表示中／非表示状態が違う場合。

選択されていない項目に応答を作らず、未観測コメントと停止を残す。
メニューへ戻る前に再表示された文章も保持するので、必要なら編集時にwhile先頭へ整理できる。
同じ選択肢名だけで、独立した会話や異なるNPCをループとして結合することはない。

## 根拠と書式

### 同一応答から次メニューへ合流する場合

最初のmenuで全選択肢の応答が観測され、各応答が同じ文章・next等の列を経て
同じ次メニューへ進む場合、最初の応答を1つにまとめてから次メニューの観測を集約する。
最初のmenuはラベルなしのまま共通本文を続け、次メニューの選択肢別の応答を保持する。
次メニュー以降の観測済み選択肢が異なっていても、その違いだけで共通本文を複製しない。
ループ化はこの合流処理の後に行うため、別の初回応答で観測した終了経路もwhile内へ反映される。

最初の全応答が揃わない場合、次メニューまでに文章・命令・観測時間差が異なる場合、
入力や未知の境界・矛盾ブロックを挟む場合は共有しない。
合流先の未応答メニューは集約対象とせず、同じ名称だけで異なるメニューをまとめない。
会話中の資源変化が異なる試行では、従来と同じく同一応答の共有を抑止する。
合流先の同じ選択肢に複数の結果があれば、従来の無条件{}ブロックで残す。
元の選択番号・応答対応・根拠ノードは変更しない。

変換は出力用の有限なツリーへ投影して行う。元の会話step、統合ノード、パケット番号、
タイミング、資源変化の観測記録は変更しない。実際に循環するグラフは作らない。
処理上限を超えた場合は例外で停止し、部分的なコードを返さない。
while_open、continue、loop_reviewはconfig/auriga/dialogue.jsonで編集できる。
古い書式ファイルでは既定値を補う。

[Auriga公式script.c](https://github.com/auriga/auriga/blob/master/src/map/script.c)の構文処理を
2026-10-27に照合。continueはswitchを越えて直近のwhile等へ移動する。
Auriga本体での実行確認は未実施。
