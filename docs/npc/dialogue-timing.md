# 会話の時間経過と反復比較

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

「会話・コード」の下側に「時間経過」「根拠JSON」を置く。
時間経過は開始からの経過、直前との差、入力要求から応答までの時間、
区間の種類、操作、PacketID、時刻の問題を表示する。
行を選んで「根拠パケット」、または行をダブルクリックすると、該当パケットへ移動する。

## GUIで反復を比較する

「会話・コード」で会話を選び、下側の「反復比較」タブで「選択NPCの反復を比較」を押す。
現在のワークスペースから、マップ・名前・外見・XYが一致するNPCの会話だけを対象にする。
同じ意味イベント経路の入力を挟まない区間を、既存のCLIと同じ判定で集計する。
複数ログを読み戻したワークスペースでも利用できる。

上の表は経路・観測数・最小／中央値／最大・幅と、比較不足／反復一致／変動ありを表示する。
3観測未満は比較不足。反復一致でも、通信遅延や他ユーザー操作を排除した証明ではない。
入力待ちは応答済みの件数と未応答の待機を分けて表示し、自動進行の比較には含めない。
配置未特定のNPCは比較できず、品質条件で除外した区間数も表示する。

比較群を選ぶと、下の表に各試行の出典・取得世代・会話番号・時間差と区間両端のPacket番号を表示する。
試行を選び「区間開始の根拠」「区間末尾の根拠」でパケットへ移動できる。
出典はログフォルダ名を表示し、ツールチップで絶対パスを確認する。

比較はボタン操作で行い、取得中の全会話比較を毎回自動実行しない。
観測の追加や別NPCの選択で古い結果を無効にし、再比較前の保存・根拠移動を防ぐ。
「比較JSON保存…」は対象NPC、元タイムライン、比較群・全試行の根拠とログ出典を保存する。
元ログへの上書きを拒否する。比較対象は最大100000観測、保存JSONは最大32MiB。
待機命令・OnTimer・起因条件・サーバーの設定値は生成しない。

### GUI反復比較の検証

全247テスト通過。3試行の反復一致、10秒の入力待ちの除外、区間両端への移動、
JSON保存と元データ保持、元ログの上書き拒否、観測更新後の結果無効化を確認した。
20261027-193248-fcdc039cでは、2会話のNPCに3比較群（各1観測、106.615/100.28/117.045ms）、
4会話のNPCには比較群0件。GUIと既存の比較関数の集計一致を確認した。
3比較群はすべて比較不足であり、タイマー設定の復元成功として扱わない。
同ログフォルダにtiming-comparison-npc-1.json、timing-comparison-npc-2.jsonを保存した。

## 区間の意味

- 入力応答まで: next/menu/input/closeの要求と対応するSENDの間。
  プレイヤーが考えた時間・通信遅延を含み、NPCの自動タイマーに数えない。
- 入力待ち中: 要求後、応答前に届いたカットイン等。自動進行の比較対象に数えない。
- 操作後の応答: 会話開始／入力応答SENDの直後のRECV。通信・サーバー処理の時間を含む。
- 入力を挟まない間隔: 待機要求がない状態の連続RECV。
  100ms以上を時間関係の比較対象にする。この閾値は表示上の小差を除くためで、
  元コードのタイマー単位を示すものではない。
- マップ移動: 終端として実際のパケットを残す。ワープ命令やイベント所有者は推定しない。

入力要求と応答の間に演出がある場合、「直前から」と「入力要求から」は異なる。
応答未観測はduration_ms=nullで保存し、最後の観測までの長さを別項目に持つ。
終了までの待機時間を0や確定値として補完しない。

## 品質と比較条件

会話開始未観測、途中取得、時刻不正／逆行、応答不整合、要求重複、会話中断等の
品質フラグがある会話は反復比較から除外する。時刻逆行の間隔はnullで保存する。
通常の入力待ち自体は品質低下として扱わない。

同じNPCのマップ・名前・外見・配置座標がすべて確認でき、開始からその時点までの
意味イベント列が一致する場合にだけまとめる。選択番号、台詞、入力値を含む経路全体を
ハッシュで照合する。未識別NPCや別配置、別分岐は混ぜない。
ログの絶対パス・取得世代・会話番号を観測単位として重複集計を防ぐ。
同一ログを別ファイルへコピーした場合の同一性は判定しない。

比較群ごとに件数・最小・中央値・最大・幅と根拠を保存する。
3観測未満は反復不足。3観測以上で最大−最小がmax(20ms, 中央値の5%)以下なら
観測間隔が一致、超えたら変動ありとする。これらは観測の比較基準にすぎない。
実装関数の引数で閾値を変更できる。

時刻は完成パケットを渡したTCPセグメントの取得時刻であり、サーバー内部の実行時刻ではない。
TCP再構成・再送・バッファリング・OS/Npcapの遅延が影響する。
PacketEventだけでは欠落／遅延の完全性を証明できないため、transport_qualityは
常にnot_verifiedとする。オフライン出力にはTCP解析エラー・未完ストリームも保存する。
既知の欠損や再構成遅延がある記録は、その診断も併せて確認する必要がある。

一致した場合もserver_timer_confirmed=falseを維持し、sleepやOnTimer命令へ自動変換しない。
Auriga本文には比較対象の時間差をコメントで残す。書式は
config/auriga/dialogue.jsonの任意キーobserved_gapで変更する。
古いカスタムプロファイルでこのキーがなくても読み込める。実行命令列は変わらない。

## 保存とログ再解析

会話JSONはschema_version=2。既存のconversationsに加え、timelines、timing_summary、
source_sessionsを保存する。元のPacketEventとSQLite列は変更しない。

単一ログは従来のtools.analyze_dialoguesで再構築できる。
複数ログの比較は次を使う。

```powershell
python -m tools.compare_dialogue_timing logs/SESSION1/capture.jsonl logs/SESSION2/capture.jsonl --definitions client/PacketLength.extracted.txt --output logs/dialogue-timing-comparison.json
```

生バイトを保存したログと、対象バージョンに一致する長さ定義が必要。
定義ファイル・入力ログへの上書きは禁止する。表示テンプレートは解析に使わない。

2026-10-27検証では、旧ログの入力なし受信間隔は同一取得時刻だった。
新ログに101.522msの入力なし受信間隔が1件あるが、途中取得の品質フラグにより
excluded_gapsへ分離し、反復比較の対象から除外した。比較群は0。
旧ログのメニュー応答まで約11.7秒は入力待ちとして分離した。
タイマー値は確定していない。
合成データで時間差、未応答、逆行、反復一致・変動、経路分離、GUIを検証した。

会話外NPC演出の[手動基準点比較](event-trials.md)を追加した。
演出／MOB出現を含む共通イベントタイムライン、複数回取得による実イベント検証、
明示的に確認したタイマー候補のコード化は今後の対象。


## 未応答終了の待ち区間（2026-10-30）

未応答のnext/menu/input/closeに対してサーバーcloseが届いた場合、記録済みのtimeout_suspectedと
要求の種類・step位置が現在の未応答要求に一致するときだけ、unanswered_terminationとして分離する。
重複要求とは表示せず、元要求のwaitsにcomplete=false、duration_ms=null、observed_until_ms、
終了step／Packetとtermination_reason=server_close_without_replyを保持する。
終了close自体の応答待ちと、元の入力要求の未応答区間を別々に残す。

GUIの区間は「未応答のまま終了」、品質理由は「未応答のままサーバー終了（タイムアウト疑い）」。
入力が完了した時間として扱わず、反復時間候補から除外する。経過30秒・60秒による原因判定は行わない。
元要求の記録が合わないcloseや通常の重複要求は、従来のoverlapping_prompt判定を維持する。

会話統合では既存の前方一致・追加観測制約を満たす未応答終了のみを正常側へ整理する。
品質フラグを消して正常な完全観測に変更するものではない。古い重複要求フラグも互換判定に残す。
実ログ20261029-215033-0a6328faの会話6(menu)、18(next)で確認し、統合本文10群は不変。
関連16項目の選択テストが通過。実行コードや元ログを変更していない。


## OnTouch候補の開始未観測表示（2026-10-30）

配置・移動を根拠とするOnTouch候補はクリック開始がない場合がある。
タイムラインのstart_unobservedは保持しつつ、GUIにはOnTouch候補であることと範囲の根拠を補足する。
歩行先からの候補では「到着を保証しない」「最小3×3セル」を明示する。
開始時刻・到着・サーバー側の起因を補完せず、完全な反復時間の集計へ昇格させない。
実ログの例は[クリックなしwarp候補](npc-file-export.md#実ログのクリックなしwarp候補2026-10-30)を参照。

## 接触試行の比較表示（2026-10-31）

同じNPC識別の複数OnTouch候補を、試行ごとの座標・符号付きdx/dy・position_basis・
歩行SEND／受信歩行／転送Packet・候補選定理由で比較表示する。
比較は検証支援であり、反応しなかった方向や正の最大距離から範囲上限・OnTouch確定を作らない。
暫定半径1は既定の仮値のまま残す。詳細は[接触候補とwarp分類](npc-bundle-export.md#接触候補とwarp分類)。


## 本人宛て関連通知の観測専用行（2026-10-30）

記録済みの本人宛て頭上通知を、対象会話のタイムラインへplayer_notification行として表示する。
取得世代・フロー・会話ID・会話NPCのActorIDと、直前step／Packetの範囲を照合する。
別会話・別フローや範囲不一致は取り込まず、同じ根拠の重複は表示だけでまとめる。
受信対象PLAYERのActorIDと会話NPCのActorID、本文、会話中／入力待ち／close待ちの文脈を区別する。

行はobservation_only、candidate=false、cause_confirmed=falseで、入力応答完了や自動実行命令とは扱わない。
delta_msとwait_duration_msは空欄。元のNPC行の時間差・waits・反復候補・品質判定は変更しない。
通知本文をConversation.stepsや生成コードへ挿入しない。表示順はPacket順とし、元Packetへ移動できる。
会話統合ONでもタイムライン自体は選択中の元会話を表示する。全寄与の通知は対象別確認欄で確認する。

GUIとDialogueStore.snapshotの保存JSONで同じ投影を使う。player_notification_countと
player_notification_omittedを保存し、詳細は1会話1000件まで。超過も総件数へ含め、元の観測を削除しない。
対象別確認欄とタイムラインの通知索引は共通化し、保存時は全会話用の索引を一度作る。

関連18項目を選択して確認。既存新ログ20会話を保存根拠から再構築し、追加カウンター以外の
タイムラインと時間集計が不変であることを確認した。player-notification-timeline-review.jsonへ保存。
会話中の本人通知・1000件超の表示・元Packet移動は合成テストで確認した段階で、実例の採取完了とはしない。
同時に、未応答終了テスト1件のファイル末尾配置による検出漏れを修正し、明示指定でも通過を確認した。


## 待機中の表示設定と未応答終了の統合（2026-10-30）

未応答終了のcloseを除く会話の前方一致に加え、最後の入力待ち中に観測した
messize/mespos/mesalignの値・順序・件数を、正常に応答した側と完全照合する。
対象はnext・menu・数値input・文字input。通知は要求後かつ応答／未応答終了closeの前で、
取得・フロー・命令形式が整合し、Packet順と時刻順も矛盾しないことを必要とする。

一致した場合だけ未応答側を部分観測として統合する。正常側の生成命令は一度だけ出力し、
部分観測は演出一致の反復回数へ加算しない。根拠JSONのtimeout_normalizationsに
matched_wait_layout_observationsを追加し、元の未応答終了と設定通知を残す。
値や有無が異なる、順序・件数が異なる、別フロー、区間外等の場合は統合しない。
表示設定以外の待機中追加観測に対する既存の要確認条件は緩めない。
30秒／60秒等の時間閾値や未観測の応答を補完する変更ではない。

対象10テストを確認。実ログ20261029-215033-0a6328faの20会話・10統合群・既存の未応答統合2件と
生成コードは維持された。待機中設定と未応答終了が同時にある実例は未確認で、今回の4入力種別は合成検証。
当該ログのwait-layout-timeout-review.jsonに入力ハッシュと既存出力比較を保存した。
