# 演出・会話開始・マップ到着の基準点比較

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

主画面の「演出比較」タブで、会話外のNPC演出を基準に観測列を比較する。
「別ウィンドウ…」で比較状態を保ったまま独立表示でき、「主画面へ戻す」または閉じる操作で戻れる。
元のイベント起因・変数条件・タイマー設定を判定せず、NPCコードへの命令追加もしない。
別操作で[試行を手動採用したタイマーラベル候補](event-timer-candidates.md)を作成できる。
比較結果自体を自動で命令化する処理ではない。
同じNPCの演出でも他ユーザー操作に起因する可能性があるため、結果は観測候補として扱う。

announceはActorIDを含まないが、選択した基準点と同じ取得・通信フローの観測窓内にあれば
関連観測として比較する。会話中や入力待ち、close応答待ち中のannounceも対象とする。
本文・装飾値・有無の違いは観測列の不一致として残し、別フローの通知は含めない。
元観測のactor_id・target_observedは変更せず、採用理由をselected_timer_window_same_flowとして保持する。
announce自体を対象NPC既知の基準点にはできない。

BGM（07FE/0B8C）も同じ取得・フロー・観測窓の関連通知として比較する。
曲名、種別（未指定と数値も区別）、有無・順序を保持し、別の既知MAP・MAP世代は除外する。
ActorIDは未特定のままで、BGM自体をNPC基準点にはできない。GUIの試行詳細に「BGM（対象未特定）」と表示し、
曲名・種別と根拠Packetを確認できる。反復一致でもNPC起因とは確定しない。
ローカルAurigaのmusiceffectはプレイヤー紐付けを必要とするため、BGMを含む試行のNPCタイマー自動生成はしない。
手動採用時も未対応として拒否し、BGMを黙って落としてタイマー候補を作らない。全373テスト通過。

インスタンスMAPでは他ユーザー起因の可能性があるannounceも観測窓内に保持し、他演出と同じ列で比較する。
受信時のmap_context（MAP名・世代）とinstance_modeを記録する。既知のMAP・世代が基準点と異なる通知は除外し、
別MAP・再入場後の通知を混ぜない。NPCの直接対象と断定するフラグは変更しない。

## 比較基準の切替（2026-10-29追加）

「比較基準」で会話外演出・会話開始・マップ到着を選択する。一覧には対象演出と基準点を表示し、
**同じ種類の基準点を2〜20件**選んで比較する。基準点も根拠Packetへ移動できる。

- 会話外演出: 従来の同じNPC・同じ演出を基準とする。
- 会話開始: クリック開始、または観測したOnTouch会話の先頭を使用する。配置が判明した同じNPCと
  同じ開始形式だけを比較する。対応済みの会話内演出と会話外演出を含め、入力待ち・close応答待ちは除外する。
  次の会話開始またはMAP移動で観測窓を区切る。開始が未観測の会話にクリックを補完しない。
- マップ到着: 0091／0092の受信を使用する。キャラクタ選択のMAP名は到着パケット扱いにしない。
  同じ取得・通信フロー・MAP世代の会話外演出を比較する。複数対象は名前・class・座標等も照合し、
  対象不明なら不明のままID等を保持する。MAP移動で観測窓を区切る。NPC起因とは断定しない。

新しい2種類は観測比較とJSON保存まで。NPCタイマーへの直接変換は拒否し、
従来の演出基準点と全時刻手入力による採用を維持する。対応演出を共通の列で照合する段階であり、
会話命令すべての比較やサーバー側イベント・条件・待機時間の復元ではない。
同じインスタンス基底MAP名・NPC名への投影は比較識別に使用し、元の名称とMAP世代は保持する。

GUIで新しく保存する基準点設定には比較基準も含まれ、照合成功後に復元する。旧形式では保存時と同じ「比較基準」を選択する。
既存の演出基準点設定JSONも従来のモードで再開できる。
会話開始は保持中の会話、MAP到着は最大2000件、比較行は最大14000件を対象とし、上限は通知する。
MAP基準点保持の欠落も品質情報・GUIに表示し、全件取得済みとは扱わない。

## 操作

1. 「演出一覧を更新」で現在保持している並行・会話外演出を表示する。
2. 同じNPC・同じ演出内容の行をCtrl等で2〜20件選択する。各行を基準点とする。
3. 観測窓を1〜60000msで指定し「選択基準点で比較」を押す。
4. 結果JSONを確認し、必要なら「保存・再開… → 比較結果JSONを保存…」で
   全試行・値・時刻・パケット番号・出典を保存する。
   「選択行の根拠」は現在行の基準パケットへ移動する。

## 基準点と観測窓を保存・再開する

「保存・再開… → 基準点と観測窓を保存…」で、選択した2〜20基準点と観測窓を別のJSONへ保存できる。
生バイト記録済みログの出典が必要。取得停止後の保存を推奨する。
この設定は既存の作業プロジェクトへ自動保存されないため、別途保管する。

同じログをGUIへ読み戻し「保存・再開… → 保存した基準点を読み込む…」を選択する。
ログのSHA-256・サイズと、演出観測列の照合情報が一致する場合だけ基準点を復元する。
ログを移動・改名した場合や、複数ログの読込順で取得世代・全体のPacket番号が変わった場合も再開できる。
同時刻・同内容の重複演出は、そのログ内の出現順で区別する。

保存JSONのパスは参考情報に限定し、自動でそのパスを開かない。
現在のワークスペースで読み戻したログだけを照合対象とする。
同じログ内容が複数取得に存在して一意に照合できない場合、基準点・演出列が変わった場合、
保存後に追記・変更されたログは読み込まない。定義・意味デコードの変更で観測列が変わった場合も選び直す。
単なる表示書式の変更で意味観測が変わらなければ再開できる。

復元するのは基準点・観測窓・比較モード・会話アクション追加設定で、過去の判定や比較結果は読み込まない。
選択を確認して「選択基準点で比較」を押す。不一致・不正ファイルの読込失敗では、
現在の選択・観測窓・比較モード・追加設定・比較結果を変更しない。

GUIの新規設定JSONはschema_version=2、kind=event_trial_selection、最大64KiB。
comparisonにmodeと真偽値include_actionsを保存する。会話アクション追加はdialogue_startでのみ有効。
旧schema_version=1も読込可能で、この場合は現在の比較モード・追加設定を使用する。
設定を指定しない既存の保存APIは旧形式を維持する。
照合するログは最大20件・合計128MiB。ログが照合処理中に変わった場合も停止する。
元ログへの上書きは拒否し、設定保存は一時ファイルから置換して、失敗時に既存設定を保つ。

## 結果の読み方

下側の「試行・演出」タブに、試行番号・採否と除外理由・観測列の番号・演出数・
入力待ち等による除外数・基準Packet・参照との最初の相違を表示する。
参照は最初の比較可能な試行で、元の正しい動作と認定した試行ではない。
観測列番号が同じなら演出の順序・内容が一致するが、時間差まで同じとは限らない。

内容が異なった位置、参照より後続が未観測・追加観測だった位置を表示する。
未観測は欠落の確定ではなく、観測窓・別操作・他ユーザー由来などの可能性を残す。
除外試行は「比較対象外」とし、未観測分岐やタイマー値の補完に利用しない。

試行行を選ぶと、その試行の各演出について基準からのms・種別・観測内容・Packet番号・対象・
タイマー扱い・参照との差を表示する。
演出を選び「結果の演出の根拠パケット」で、基準点以外の後続演出にも移動できる。
除外試行の生の観測も確認可能だが、採否は変わらない。
「結果JSON」タブと保存JSONには従来通り全比較結果を保持する。
基準点・観測窓・観測データの更新では両一覧も消去し、古い結果からの根拠移動を防ぐ。

### 共通イベント列に載せる／載せない種別（#17）

共通イベント列（試行内の演出一覧）は、比較窓内で採否に残った観測の照合表示である。
手動タイマー採用の可否とは別のレイヤで扱う。

載せる（比較列の候補）:

- 通常の演出基準・マップ到着: `outside_dialogue` の会話外演出。announce／BGM／mapcell 等の
  対象未特定関連観測も、取得・フロー・MAP世代の条件を満たせば列に含める。
- 会話開始基準: 上記に加え `during_dialogue` の関連演出。会話アクション追加時は投影した
  5種アクションも対象になる（入力待ち・close待ち等は除外）。

載せない（除外理由として別タブ）:

- `input_wait` / `close_wait`、演出基準時の `during_dialogue`
- `external_candidate`、`outside_visibility`、`review_only`、`after_close_reply`
- 作用先の別MAP／省略名／配置不足、基準と異なる対象・MAP世代、次境界以降
- 時刻不正・逆行、1試行1000件の保持上限

タイマー扱い列は手動採用側の区分だけを示す（OnTimer値は生成しない）:

- 実行命令候補（command）: emotion／effect／effect_remove／announcement／unittalk／overhead／classchange（setnpcdisplay）／visibility_action（cloak・自身／hide・インスタンスMAPのみ）／viewpoint（対応範囲）／event_marker（showevent）／npc_display_action（会話外09xx setnpcdisplay）
- コメント採用のみ（comment）: effect_value／hat_effect／colored_speech／progressbar（対象付き・秒数はOnTimerへ使わない）
- タイマー拒否（rejected）: sound／music／progress_action／mapcell／会話レイアウト／
  status_action／script_command など。比較列には載せられても採用入口で拒否する

相違・除外理由の表示は `日本語（code）` 形式（例: `対象が異なる（target_changed）`、
`close応答待ち中（close_wait）`）。未知の code は生値のまま出し、KeyErrorで画面を止めない。
ツールチップにも安定な code を残す。比較JSONの構造・採否・時間集計は変更しない。

### 対象差・参照側と除外した観測（v0.0.4保存後の開発）

マップ到着基準では対象の名前・class・座標等も観測列の照合対象とする。
演出内容が同じでも対象が違えば、試行一覧と演出行に「対象が異なる」と表示する。
既知NPCのActorIDが違うことだけでは新たな矛盾とせず、比較処理と同じ識別を使う。

演出行を選ぶと、選択試行・最初の比較可能な参照試行の対象、内容、時間差、Packetを並べる。
現在側と「参照側の根拠パケット」を別々に開ける。参照側だけに観測がある行も表示するが、
受信欠落や未観測処理の存在を断定しない。同じ位置同士の照合であり、挿入・欠落の自動整列はしない。
品質除外された試行は確認表示に留め、比較対象へ昇格させない。

「除外した観測」タブは、同じ取得・通信フローの窓内候補について、入力待ち・close応答待ち・
会話中・別NPC候補・対象違い・MAP世代違い・次の境界以降等の理由を表示する。
除外観測も根拠Packetへ移動できる。別フローや観測窓外の全履歴を列挙する画面ではない。
詳細は1試行1000件まで、超過分は理由別件数と省略数を表示する。

この確認情報は元観測からGUIで導出し、比較JSONの既存構造、観測列の採否・時間集計、
タイマー候補の根拠を変更しない。再確認時は同じ生ログと基準点を読み戻す。
観測や基準・窓を更新した場合は詳細と参照先を消し、古い結果への移動を防ぐ。

### 時間差集計

「時間差集計」タブでは、同じ観測列の演出ごとに試行数・最小・中央値・最大・幅を表示する。
時間は基準点からの経過msであり、直前演出との間隔や元スクリプトの待機時間ではない。
演出1は基準点自身なので集計せず、演出2以降を表示する。演出欄のツールチップで内容を確認できる。
観測列が異なる試行は別々に集計し、除外試行は含めない。

判定は各演出の試行数と時間差の幅に基づく。3試行未満は、幅が0でも比較不足とする。
同じ観測列の中でも、安定している演出と変動している演出は別判定で表示する。
後続演出が未観測、または全試行が品質除外なら集計行はない。

集計行を選ぶと下の表に各試行の実測ms・Packet・取得世代・出典を表示する。
試行を選び「選択した時間差の根拠パケット」で、該当演出へ移動できる。
基準点へは「試行・演出」タブの演出1から戻れる。
出典はログフォルダ名を表示し、ツールチップで絶対パスを確認する。
古い結果の無効化は時間差集計と実測値一覧にも適用する。
集計は既存の比較JSON内のvariants/timingsを表示するもので、判定方法や保存形式は変更しない。

基準点は対象が判明したNPCの会話外演出に限定する。
配置のマップ・名前・外見・XY・向きと、演出種別・内容の一致を確認する。
対象不明、MOB、対象IDを持たないcutin、入力待ち中の演出は基準点に使わない。
会話開始・マップ到着は上記の切替で対応済み。MOB出現基準の比較は未対応。

## 比較の範囲

各試行は同じ取得世代・フロー・ActorID・マップ世代・出現記録の中で、
基準時刻から観測窓末尾まで（両端を含む）を対象にする。
別対象・別出現・別マップ世代を混ぜない。
入力待ち中等の演出は別に数えて比較列から除外する。
試行ごとに基準点からの時間差と元の演出観測を保持する。

選んだ同一対象の観測窓が重なればoverlapping_windowsとし、独立した反復として数えない。
時刻不正・逆行、途中取得、1試行の保持上限到達もquality_flagsへ記録して比較群から外す。
演出の順序・内容・件数が異なる試行はobserved_differenceとして別variantに残す。
これは混入・欠落・未観測の入力等の可能性を示す注意で、原因の判定ではない。

同じ観測列が3試行以上あれば、対応する演出の基準点からの時間差について
最小・中央値・最大・幅を集計する。幅がmax(20ms,中央値の5%)以下なら観測上の反復一致とする。
それ未満は比較不足。基準点以降に演出がなければno_followup_observedで、時間設定を作らない。
観測窓に全イベントが収まった証明はできないため、coverage_verified・cause_confirmed・
server_timer_confirmedは常にfalse、通信品質はnot_verifiedを維持する。

一覧更新後に観測が増えた場合は、一覧を更新して基準点を選び直す。
基準点・観測窓の変更で比較結果を消去し、古い条件での保存を防ぐ。
元の会話・演出記録・生成コードは変更しない。元ログへの保存上書きは拒否する。
一覧は最大10000件、1試行は最大1000演出。結果プレビューは20万文字、保存JSONは最大32MiB。

## 除外理由と時刻問題の根拠（v0.0.4後の開発）

「除外した観測」に、入力待ち・対象違い等に加えて、時刻不正、時刻逆行、1試行1000演出の保持上限を表示する。
時刻の判定は比較本体と共通化する。除外された観測にも元Packet番号を保持し、根拠へ移動できる。
経過msを計算できない場合は「算出不可」。逆行の場合は有効な差分を表示するが、観測窓内の正常な時刻とは扱わない。
時刻問題の観測を時刻補完で比較列へ戻すことはしない。

同じ取得・フローと基準点以降の観測順を確認し、比較の時刻判定が問題とした行を表示する。
時刻が不正な行の窓内位置を断定せず、別対象・次境界・窓外の観測をむやみに時刻問題へ含めない。
保持上限によって比較を打ち切った後の窓内候補も、その理由で示す。
詳細は最大1000件、理由別件数と詳細省略数はそれとは別に保持する。
試行一覧の「入力等除外」は入力・並行状況の件数であり、対象違い・時刻問題・上限も含む詳細理由の総数とは範囲が異なる。
