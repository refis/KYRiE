# 会話外演出からの手入力NPCタイマー候補

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

「演出の基準点比較」→「試行・演出」で試行を選び、
「選択試行から手入力タイマー候補を作成…」を押す。
採用するのはその試行だけ。比較内の他の観測・相違・品質情報は保存根拠に残す。
通常の会話生成・矛盾ブロックの規則や、元の観測列は変更しない。

## 時刻と確認

announceを含む観測列も手動採用できる。対象未特定のannounceは、比較で選んだ同一取得・同一フローの
観測窓内の関連候補であり、NPC起因が確定した通知としては扱わない。生成書式はevent_timers.jsonに分離。
本文・装飾値・有無の相違を比較根拠に残したまま、採用試行と全時刻を利用者が確認する。

各演出の時刻欄は空欄から始める。基準点自身を含む全演出に、1〜2147483647msの整数を入力する。
観測基準からの経過ms、中央値、最短値、0ms等を自動採用しない。
NPCタイマーのカウント開始からの手入力時刻であり、元の待機時間を復元した値ではない。
観測順で同じか増える時刻を指定する。同時刻の演出は順序を保持して1つのOnTimerラベルへまとめる。
OnTimer0は生成しない。照合したAurigaでは、開始時のカウントより大きいタイマーから実行する。

対象NPC・採用試行・全手入力時刻と、未観測・他ユーザー由来の可能性を確認してチェックする。
「候補を表示」でプレビューし、JSON保存で設定と全比較根拠を保存する。
比較不足や観測列の相違がある場合も、利用者が明示した手動採用として扱う。
その状態を消去したり、元のタイマーが確定したことに変更したりしない。

品質除外の試行は採用できない。基準点を含む2〜200演出に限定する。
観測や比較条件が更新された場合、候補画面を閉じて再比較する。
時刻・確認の変更で以前のプレビューを消去し、古い表示を新しい設定として使わない。

## 出力範囲

手動採用できる演出（対象NPC自身・会話外。announceは選択窓の関連候補）:

| 種別 | 出力 |
|------|------|
| emotion / effect / effect_remove | 実行命令（Auriga: emotion / misceffect / delmisceffect） |
| unittalk | 実行命令（unittalk） |
| overhead | 実行命令（showmessage）。対象NPC自身のみ |
| announcement | announce（関連候補・起因未確定の注記付き） |
| effect_value / event_marker / hat_effect / colored_speech | **全行コメント**。実行命令へ落とさない |
| classchange | 実行命令 `setnpcdisplay {NPC名},{class_id};`（対象NPC自身・会話外の手動採用時）。kind は根拠のみ |
| visibility_action | `cloakonnpc;`／`cloakoffnpc;`（対象NPC自身・会話外・引数なし。自身発生は受信者本人のみのため採用可）。`hideonnpc;`／`hideoffnpc;`はインスタンスマップ（MAP名に`@`）上の自身向けのみ。通常MAPの hide・他NPC向け target 付きは拒否 |
| viewpoint | 実行命令 `viewpoint {kind},{x},{y},{marker_id},{color};`（対象NPC自身・会話外。種別1／2・座標0〜1023・marker 0〜255のみ。未対応値は拒否） |

未対応のまま拒否する種別（比較列には載せられるがタイマー採用不可）:
sound、music、progressbar／progress_action、mapcell、会話レイアウト、
status_action、script_command、npc_display_action など。
効果音・BGMはプレイヤー紐付けが必要で、NPCタイマー本文へ置いても同動作を再現できない。
未対応演出を含む試行は、黙って省略せず拒否する。

候補は既存の対象NPC本文へ統合するラベル断片。NPC宣言は生成しない。
先頭にendを置いて通常処理からの流入を止め、各ラベルもendで閉じる。
OnInit・initnpctimer・startnpctimer・ループ・変数条件は生成しない。
タイマーをいつ誰が開始するか、既存OnTimerラベルとの重複、演出の配信範囲は別途確認する。
実行命令の既定の配信範囲が元のサーバーと一致するかは、受信だけでは確定できない。

書式・注意文・インデントはconfig/auriga/event_timers.json。
ラベル時刻・命令と演出ID・end終端の整合性を検証し、注意文・根拠は全行コメントに限定する。
開始条件の追加や別命令への変更は、この書式では対応しない。

JSONのaurigaにコード、manual_times_msに手入力時刻、trial_indexに採用元、target_npcに配置識別、
source_reportに採用しなかった試行も含む全比較根拠を保持する。
setting_origin=manual_review、adoption_confirmed=trueで明示し、
cause_confirmed・server_timer_confirmed・automatic_start_generatedはfalseを維持する。
候補は最大4Mi文字、JSONは最大32MiB。元ログ・生成書式への上書きを拒否し、保存は一時ファイルから置換する。
作業プロジェクトへの組込み、NPCファイルへの自動統合は未対応。

## 保存した手入力時刻を再編集する（2026-10-28）

同じログ・基準点・観測窓で比較を作成し、同じ採用試行の編集画面から
「同じ比較根拠の設定JSONを読み込む…」を選ぶ。
対象NPC・試行番号・採用しなかった試行を含む全比較根拠・確認フラグ・生成コードを照合し、
手入力時刻を現在の生成書式で再生成して一致を確認する。別の比較や試行、改変されたコード、
重複キー・非有限数・32MiBを超えるJSONは拒否する。生成書式を変更した場合も一致が必要。
ログの追加・並べ替え・基準点変更で比較根拠が異なる場合は、自動で設定を移し替えない。

成功時は手入力時刻だけを編集欄へ戻し、確認チェックとプレビューを解除する。
観測時刻の自動代入・開始条件の生成は行わない。
時刻を変更した場合も確認を解除するので、全時刻を再確認してチェックする。
不正な読込では入力中の値を保持する。取得・比較条件が更新された画面では読み込めず、再比較が必要。

回帰テストでは同じ比較からの復元、採用試行・根拠・コード・確認フラグの変更拒否、
入力変更後の再確認、不正読込時の保持、古い比較画面での拒否を確認した。
合成試行による検証であり、実在NPCのタイマー設定を確認したものではない。

## 根拠付きテキストへ出力する（2026-10-28）

確認チェック後に「確認済み候補を根拠付きテキスト保存…」を選ぶ。
先頭のJSONコメントに全比較根拠・採用試行・手入力時刻・確認状態を保持し、
続けて現在の書式から再生成したAuriga候補を出力する。
出典・NPC名などに改行があってもJSON内でエスケープし、追加命令として扱わない。
保存する生成コードと根拠・確認状態が一致しない候補は出力しない。
自動開始・再開・ループ命令や、未観測の起因条件は追加しない。

これはNPC本文へ手動統合する編集用候補で、単独の配置宣言ではない。
配置先NPC、既存OnTimerラベルとの重複、実行対象・開始方法を確認し、Aurigaで検証する。
再編集用にはJSONも保存する。テキストファイル自体のGUI再読込は未対応。

テキストも最大32MiB。保存先選択中に比較が更新された場合は拒否し、
元ログ・生成書式への上書き禁止、一時ファイルからの置換を維持する。
保存失敗時・比較更新時の既存ファイル保持をGUIで検証した。
全293テスト通過。Auriga本体での実行確認は未実施。
