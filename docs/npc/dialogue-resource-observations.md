# 会話中の所持品・Zeny・マップ遷移の観測

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

## クエスト通知

追加02B3/09F9/0B0C（107/143/155バイト）、削除02B4（6バイト）、状態応答02B7（7バイト）を保持する。
同梱MARiAの追加・削除処理とローカルAurigaの送信処理を照合。追加はID・状態値・時刻値・目標数を読み、
目標部はobjective_payload_hexとして全体を保持する。目標条件・モンスターの意味は未解析で、未観測値を補完しない。
02B7の状態値は受信値のまま保存し、クエストの完了条件とは扱わない。

会話外を含むquest_observationsを会話JSONと一括解析に保存し、会話中はresource_observationsにも関連付ける。
「並行・会話外演出」のJSONと、会話の根拠JSON・時間経過・生成候補の観測コメントで確認できる。
利用者の指定により、会話中の追加／削除通知はQuestIDだけを使用してsetquest／delquestを生成する。
受信位置に対応した会話経路へ配置し、分岐ごとのID・命令の違いを維持する。条件式・報酬は生成しない。
入力待ち中の通知は、観測した応答の後へ注記付きの候補として配置する。応答未観測なら命令は生成せず根拠コメントを保持する。
会話外の通知は原則として会話へ挿入しない。ただしclose応答後2秒以内の同一取得・同一フローの追加／削除は
既存のclose2継続候補として保持し、close2→クエスト命令→endで出力する。応答前・別フロー・期限外は含めない。
後続通知を受けても元の応答からの判定窓は延長しない。状態／目標更新だけではclose2へ変更しない。
書式はdialogue.jsonのquest_set／quest_delete／quest_wait_review。
入力応答の対応を維持し、クエスト通知も既存のclose継続判定に合わせて扱う。
同じメニューへ戻る経路にクエスト命令がある場合もwhile整理に対応し、命令をcontinueの前に保持する。
既知の命令・QuestIDの差を消去して共有せず、隠れたcheckquest条件や実行確率は生成しない。全383テスト通過。
保持上限は演出観測と同じ設定値を使い、未保存数をquest_droppedへ記録する。異常通知や容量超過は問題として残す。

### setquest／delquest と showevent（OnQuestInfo）

会話中または close2 判定窓内で setquest／delquest の後に 0x0446（event_marker）を観測した場合、
直前の未関連クエストへ結び `quest_info_links` へ保持する。
コード生成では該当NPCの `OnQuestInfo:` に
`showevent {state}, {kind}, "{NPC名}";	// {quest_id}: {x}, {y}` を追加する（Auriga）。
単一会話・統合本文・配置付き一括出力のいずれでも、OnInitの後へ付与する。
関連付け済みの event_marker は会話本文・外部コメントへは出さない。
GUIの会話詳細「クエスト」タブで setquest／delquest の時系列を確認できる。
showevent 関連がある行は OnQuestInfo 候補、無い行は「未関連」と表示する。

全376テスト通過。20261028-012526-0abe69d9で追加8件・削除6件を会話関連観測として保持し、
会話90件・統合34群・会話解析問題0件を維持した。別レポートsession-analysis-quests-review.jsonへ保存済み。

命令生成・状態参照の追加後は全381テスト通過。時間経過に「クエスト参考値（受信値）」列を追加した。
QuestID、追加／更新のstate値、削除通知、目標カウントの現在値／要求値を確認し、根拠Packetへ移動できる。
stateはパケットの受信値であり、checkquestの戻り値へ自動変換した値ではない。条件判定を考える補助とし、checkquest条件自体は生成しない。
### 目標カウント更新

02B5/09FA/0AFE/08FEの更新に対応する。総長・レコード幅・明示件数（08FE以外）を照合し、
ローカルAurigaで確認した1通知あたり最大3目標の範囲で扱う。空通知は0件として保持する。
02B5/08FEのobjective_idはMOBクラスID、09FAはクエスト目標ID、0AFEは目標IDと別の目標インデックスとして区別する。
objective_kindとlayoutに根拠を残し、目標IDを一律にモンスターIDへ変換しない。
required_count/current_countは受信値を保持し、大小関係から値を修正したりクエスト完了と判定したりしない。

会話中はquest_countの関連コメントと時間経過、会話外はquest_observationsへ保存する。
観測ログのdecoder=quest_counterではquest_layout/quest_objective_kind/quest_entry_count/quest_entriesを外部書式に渡す。
クエスト条件や必要討伐数のスクリプトは生成しない。全379テスト通過。クエスト一覧全体の復元は未対応。

有効な会話と同じ取得世代・接続フローで受信した状態変化を、会話の根拠へ関連付ける。
会話本文とは独立したresource_observationsへ保持し、入力待ち中でもプロンプトと応答の対応を変えない。
関連付けは同時に観測したことを示すだけで、NPCが原因であることや報酬・消費条件を確定しない。
全てcause_confirmed=falseを維持する。

## 対象

- Zeny通知: 直前残高がある場合は差分、ない場合は現在残高と差分不明を保持する。
  差分が既知で0の通知は追加しない。
- BaseExp／JobExp通知: ログイン／キャラ一覧の初回値は差分不明のまま残し、
  その後の増加だけ差分を保持する。差分0は追加しない。減少はメモのみ（getexp化しない）。
- アイテム増加: 成功した取得通知のID・数量・所持品Indexを保持する。
- アイテム減少: PlayerStoreで確認済みのIndexからIDと数量を解決できた場合のみ保持する。
  未観測Indexや数量不足、一覧受信中の矛盾は正常な消費として採用しない。
- マップ遷移: 会話終了境界とともに移動先マップ・XYを保持する。

所持品一覧そのものをNPCによる授受とは扱わない。
会話開始前・終了後・別接続・別世代の変化を、近いNPCへ推測で割り当てない。
受信後に解決できない通知を、後から出現した情報で遡って割り当てることもしない。

## 表示・出力

会話JSONの各会話にresource_observationsを保存する。
元パケット番号・ID・時刻・接続・取得元・世代・フロー・値と、
直前の会話ステップ番号after_step_index（0始まり）を保持する。
GUIの時間経過表には「同一接続の変化・起因未確定」の行として表示し、根拠パケットへ移動できる。
マップ移動は既存の終了境界行を使う。並行観測行はstep_index=nullで本文ステップ番号を変えない。

単一／統合本文の先頭に、試行ごとの時系列観測メモをコメントとして付加する。
これは変化が会話冒頭で起きたことや、その場で実行する命令を意味しない。
統合では取得世代・会話番号・出典を併記し、元観測は各contributionにも残す。
配置付きNPCファイルにも同じメモが含まれる。
文面はconfig/auriga/dialogue.jsonのresource_*で変更でき、旧プロファイルには既定値を補う。

getitem／delitemは所持品命令経路（script_commands）でも候補化するが、資源コメント行自体の
命令化は利用者が行ごとに `adoption_confirmed` を付けた場合に限る。
GUIの時間経過タブ「資源変化の命令採用」で切替できる。cause_confirmedは常にfalseのまま。

確認済みのときだけ本文へ出す候補:

- Zeny（差分既知）: `set Zeny,Zeny{delta:+d};`
- BaseExp／JobExp（増加のみ）: `getexp {delta},0,0;`／`getexp 0,{delta},0;`
- マップ（非インスタンス名）: `warp`。`@` を含むMAPは実行せず確認用コメント
- アイテム増減: 同一Packetの script_command が無い場合のみ getitem／delitem。ある場合は重複させない

未確認行・差分不明Zeny／初回EXP／減少EXPは従来どおりコメント／未生成。起因・報酬条件式は生成しない。
書式は dialogue.json の `zeny_set`／`base_exp_set`／`job_exp_set`／`map_warp`／
`map_warp_review`／`resource_adoption_review`。

複数選択肢の本文が同一でも、関連する増減観測や位置が異なる場合は応答同一と断定せずswitchを維持する。
全観測が一致し本文も完全に一致する場合は従来どおりラベルなしmenuへまとめられる。
単一選択肢はラベルなしmenuを維持する。
増減の観測だけを新しい会話分岐や条件式に変換せず、差は試行別コメントと根拠で確認する。

## 上限・検証

全体10000件・1会話512件。本文・並行演出・増減観測の合計も1会話2048件を上限とする。
超過は解析問題へ記録し、その会話を統合候補から除外する。既存JSONで配列がない場合は空列として読む。
時刻や世代・型などの不正な観測をコードへ差し込まない。
タイマー候補は従来の会話タイムラインに基づき、増減通知から待機・報酬の条件を推定しない。

全221テスト通過。入力応答維持、初回残高と差分、取得・消費、マップ移動、
別フロー・取得失敗・未観測消費の除外、容量制限、旧書式、GUI表示・保存、menu/switchの維持を確認した。
実ログ20261027-064450-e05d0fb7の会話へZenyとマップ遷移の2通知を関連付けた。
20261026-223425-131e9688の会話には該当通知なし。
実ログのアイテム授受とNPCによる因果関係の確認、Auriga実行確認は未実施。

所持品の増減は、観測根拠を保持したうえで会話中のgetitem/getitem2/delitem/delequip候補にも対応しました。
倉庫移動・捨て操作・精錬との重複抑止や未観測引数の扱いは[所持品等の命令](item-and-ui-commands.md)を参照してください。
