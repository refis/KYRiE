# NPC／MOB情報保持と一覧

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

## ActorIDと視界観測区間

NPC/MOBの「同サーバー・同IDの観測」タブで、選択したActorIDの観測区間を確認できる。
取得セッションとサーバーIP・PORTが同じ記録だけを列挙し、クライアントPORTの変化や視界再観測を追う。
MAP・観測区間・状態と保持中の先頭／最後のPacketを表示し、行を選んで根拠へ移動する。
「表示中のみ」の一覧フィルターに隠れた過去区間も含む。サーバー不明なら選択区間だけを表示する。
根拠は既存の直近32件であり、「保持中の先頭」は初出現パケットの完全保存を保証するものではない。
同一実体・配置順・再出現設定の確定や、スキル観測区間の自動結合は行わない。

ActorIDの名前空間はサーバーIP・PORTごとに区別する。利用者から提示された割当モデルでは、通常の
スクリプト配置NPC・再出現時間を持つMOBは読込順の連番で、視界外移動による消滅でもIDは変わらない。
メンテナンス等で配置内容が変わればIDも変わり得る。随時生成NPC、再出現時間のないイベントMOB、
インスタンス内のNPC/MOBは生成時のランダム割当として扱い、連番モデルから除外する。
例の100体ずつの配置は、先頭1001なら2種目の100体目が1200となる。ただし未観測IDを個体数へ補完しない。

appearanceは視界内の観測区間で、ActorID再割当の世代や別個体の確定値ではない。
死亡／視界消滅／再観測を区切って間隔・スキル集計の根拠を維持しつつ、
server_actor_observationsには同一取得・サーバーIP・PORT・ActorIDの観測集合を出力する。
クライアントPORTや接続のSYN番号はサーバーの識別に含めない。接続文字列を解析できなければサーバー未取得とする。
同じActorIDの観測集合であることと、同一実体・同一設定であることは分け、same_entity_confirmed=falseを保持する。
取得セッションを跨ぐ自動統合は行わない。インスタンス以外の割当方式はパケットだけでは確定せずnot_determinedとする。

NPC/MOB個体情報にサーバーと割当方式を表示する。既存entity_keyやappearanceは変更しない。
会話やスキルの区間分離は観測上の境界であり、そのたびにサーバー側でIDが再発行されたという意味ではない。

## 操作

観測を開始すると、完全に分割された受信PacketEventからNPC／MOB情報を更新する。
「NPC」「MOB」タブに名前、個体ID、外見／クラス、マップ、座標、向き、速度、状態、
更新件数を表示する。更新件数は出現回数や討伐数ではない。

行を選択すると移動先・HP・オプション・グループ／タイトルと根拠パケットを確認できる。
「最後の根拠パケット」はPacketID絞り込みを解除して、対応するパケット詳細へ移動する。
「表示中のみ」で絞り込める。既定では消滅通知済み・過去の記録も残して一覧化する。
250ms単位でまとめて更新し、更新前の選択行を維持する。

「NPC一覧を保存…」「MOB一覧を保存…」は現在の種類・表示中フィルターに合う
観測情報をJSON保存する。これは完成したNPCスクリプト／mob_skill_dbの生成ではない。
内容には接続世代・マップ世代・出現記録、観測時刻、根拠、未解決項目を含む。

## 構成

- reconstruction/decoder.py: バイト列から構造化した意味イベントを作る。
- reconstruction/world.py: 接続・マップ・個体ごとの状態と観測根拠を保持する。
- gui/entities.py: 状態を読むテーブルモデル、絞り込み、選択詳細。
- tools/analyze_entities.py: 記録済み受信セグメントを同じ処理へ渡すCLI。

表示JSONや表示文章を解析して状態を作らない。表示定義を変更してもNPC/MOB情報は変わらない。
AurigaとrAthenaの表示形式切替も意味イベントの状態管理には影響しない。

## 対応した観測

- 09FE / 09FF / 09FD: MARiA準拠の出現・待機・移動情報。
  種別5をMOB、6と12をNPCとして扱う。プレイヤーや未対応種別は一覧へ推測登録しない。
- 0ADF: 名前・グループ・タイトル。0095: 旧形式の固定長名前応答。
- 0080: 消滅通知。理由1のみ死亡通知と区別する。
- 0088: 座標修正。01B0: 外見変更。0229: 32bitの表示オプション更新。
- 0977 / 0A36: HP・最大HP／5%単位のHP割合の観測。
- 0091 / 0092: マップ変更。以前のマップの表示状態を閉じ、新しい世代に分ける。

長さ・フィールド位置はこのMARiA互換の09xx系レイアウトに対するもの。
長さ表と別のパケット構造を持つクライアントへ自動対応する機能ではない。

## 分離と未知値

個体のキーは観測セッション・接続文字列（SYN/ASSUMED世代を含む）・マップ世代・
個体ID・出現記録番号。消滅後に同じIDが現れた場合は履歴を分ける。
出現記録番号は、サーバーの再湧き回数や再湧き設定を証明する値ではない。

名前応答が先行した場合は同じ範囲内で保留し、後からNPC/MOB種別が観測できた時だけ
関連付ける。名前応答だけでNPCを作らず、別接続・別マップの名前を流用しない。
新しい観測の開始時は以前の表示状態を過去扱いにする。Qtへ遅れて届いた旧観測の
パケットも元の観測セッションへ割り当て、現在の状態へ混ぜない。

マップ名が取得できなかった場合は未取得のまま保持する。別接続へマップ名を推測で
引き継がない。途中取得では観測できた範囲しか復元しない。

cp932の不正な名前は黙って文字を削らず、nameの未解決項目として記録する。
そのパケットから正常に読めた個体ID・種別・位置等は保持する。後から正常な名前応答が
届けば解決できる。範囲外や総長不一致はその意味イベントを適用せず、取得・RAW保存を継続する。
未解決項目や構造エラーの診断には生の名前／本文を記録しない。

個体記録は最大20,000、先行名前の保留は最大4,096、根拠は個体あたり直近32件。
上限で新規個体を受け付けなかった場合は診断する。根拠には全体パケット番号と
観測セッション内番号があり、GUI保存時はセッションログの保存先も対応付ける。

## オフライン再構築

本文を記録したログから実行する。

```powershell
python -m tools.analyze_entities logs/SESSION/capture.jsonl --definitions client/PacketLength.extracted.txt --output entities.json
```

長さ定義のSHA256、TCP再解析結果、NPC/MOB観測情報、診断をまとめて保存する。
HTTPのPASSや未知IDでの停止方針は通常の取得と共通。過去のログ本文は変更しない。
JSONをGUIへ読み込む機能は今回の対象外。

## 初回出現と再観測の差分表示

NPC/MOBの初回出現は観測ログに残す。同じ取得・サーバーIP/PORT・ActorIDの
再観測では、無変化なら表示を省略し、変化があれば変化した項目だけを表示する。
インスタンスは元マップ名でも区別する。名前が読出不能の場合は通知を残す。
表示の省略は生パケット保存、HEX、個体情報の更新を止めない。
差分の文章・項目名はconfig/auriga/display.jsonのactor_change_templateと
actor_change_labelsで変更できる。履歴は上限付きであり、履歴が破棄された後は初回扱いになる。

## NPCの職業外見とclass変更

プレイヤー職業classのNPCは配置をclass 844とし、初回出現の実class・性別・髪型・
髪色・服色・頭装備・衣装等をsetnpcdisplayとしてOnInitへ出力する。
職業一覧はconfig/player_classes.jsonに分離し、参照Aurigaの職業定義に基づく。
一覧変更後は再起動して再解析する。生のclassと初回外見は保持し、後続の変更で
配置の初期classを書き換えない。必要値やNPC名が未観測なら補完せず確認コメントにする。
職業外見の通常shopにはOnInitを置けないため、補助NPCを自動生成せず確認用出力とする。

参照Auriga実装のsetnpcdisplay引数順は、NPC名・class・性別・髪型・髪色・服色・
頭上段・頭中段・頭下段・衣装・style。同梱説明書と順序が異なるため、実装に合わせている。
書式はconfig/auriga/dialogue.jsonとentity_metadata.jsonで変更できる。

視界内で受信したNPCのclass変更は、会話外も観測ログにsetnpcdisplayを表示する。
会話中は自NPC／別NPCへの変更を対象名付きでコードに含める。
専用の01B0だけでなく09FF／09FE／09FDで判明したclass変更も対象とし、
出現通知から得た職業外見の追加引数も保持する。同じ変更の再通知は重複生成しない。
会話外の変更は解析JSONのnpc_display_candidatesにも保持し、09FF／09FE／09FDのclass変更は
演出観測（npc_display_action）としても保持する。実行契機を推測してOnInitへ移植しないが、
手動タイマー候補では対象NPC自身の setnpcdisplay として採用できる
（[タイマー候補](../npc/event-timer-candidates.md)）。視界外／再出現で判明した変更は、
変更時点が未観測である旨の注意コメント付きにする。MOBの変更は差分通知と個体情報に保持する。

会話群の識別も初期配置classを使用するため、同じ配置の外見変更前後の会話を
別NPCとして分割しない。職業外見はclass844を基準とし、生の初回外見・変更観測は保持する。
初期配置class自体が異なる観測は引き続き区別する。

個体情報には初回／現在classとNPCの配置class、性別・髪型・髪色・服色・
頭装備・衣装・styleの初回／最終取得値を表示する。未取得値は未取得と表示する。
classだけの変更通知は他の外見項目を確定しないため、それらは最終取得値として参照する。
統合会話の単体配置ファイルと全NPC一括出力では、初回外見のOnInitを一度だけ保持する。

保存・読み戻しは、生TCPログからCLI解析とGUI再解析の両方を通す連携テストで確認する。
外見パケット途中のTCP分割、重複通知、class変更、消滅・再観測を含め、
初回外見とOnInit出力の一致、元ログを変更しないことを検証している。
これは合成ログでの確認であり、実ゲーム／Auriga実行の確認とは区別する。

2026-10-29点検: 自NPCの01B0も差分・視界判定を共有し、同値の再通知を命令化しない。
初回表示状態の保持は外見と同じ識別を使用し、別インスタンスMAPの同一IDとは混同しない。
外見変更の保持上限で欠落した件数は、一括解析の品質情報にも表示する。

## 一覧と一括出力の順序

NPC／MOB一覧・個体JSONは、サーバーIP（数値順）→PORT→ActorID（数値順）で表示・出力する。
同じActorIDの観測区間は取得・MAP世代・視界区間等で安定して並べ、区間を削除しない。
サーバー不明は後方に置き、接続ごとにActorID順とする。更新後も選択中の個体を維持する。
NPC一括コードとJSONのentriesも同じ順序。複数観測を統合した配置は、出典中で最小の
サーバー／ActorIDを並び順の基準とする。MOB配置集計と一括候補はグループ内の最小ActorIDを使う。
並び替えから配置数・再出現設定・同一実体の確定は行わない。

## 外見変更履歴の根拠へ移動（v0.0.4保存後の開発）

NPC／MOBの個体を選び、下側の「外見変更履歴」タブを開く。
class・髪型・装備・表示オプション・座標等の変更前後、観測時刻、Packet番号と観測状況を確認できる。
「変更の根拠パケット」で選択した通知のパケット詳細へ移動する。選択行のJSONも確認できる。
同値の再通知は履歴へ追加しない。視界外／再出現時に判明した変更は変更時点が未観測と表示する。

一覧更新後も同じ個体・同じ変更が保持されていれば選択を維持する。
個体を切り替えた場合や「表示中のみ」で対象が隠れた場合は古い参照を消す。
履歴は選択した視界観測区間で保持できた直近32件まで。初回出現は別の初回外見情報で確認し、
視界区間を跨ぐ変更の自動集約や、保持外の全変更を保証する表示ではない。
元の観測、初回class・外見、コード生成結果はこの操作で変更しない。


## 末尾のCP932文字が途切れた出現名

20261029-215033-0a6328faの09FFの6件では、offset84から23バイトの名前末尾が
CP932の先行バイトだけで終わっていた。開始位置をずらして読む根拠はなく、切り詰めを疑う診断とする。
名前の読取は厳密なまま維持し、代替文字や未観測の後続文字で正式名を作らない。

末尾1バイトだけが不完全で、そこまでの文字列を厳密に解読でき、名前領域にNULがない場合、
metadata_evidence.name_diagnosticへvalid_prefix・raw_hex・name_offset・observed_bytes・
truncation_suspected・authoritative_name=falseと取得根拠を保存する。
各出現根拠にもname_diagnosticを残す。途中の不正バイトや別形式をこの規則で読み飛ばさない。

正式名が未取得ならNPC/MOB一覧の名前欄には「接頭部分（不完全名・参考）」と表示する。
個体詳細に名前範囲と生バイトを表示し、Entity.nameやNPC名の呼出し・比較用識別には採用しない。
同じActorIDで後着の有効な名前が得られた場合は正式名を更新し、現在の参考診断を解消する。
過去の出現根拠と警告は残す。正式名の後に不完全名が届いても、正式名は上書きしない。
別の名前解読エラーに変わった場合は、古い参考接頭部分を最新の診断として表示し続けない。

実ログの対象Packetは503,505,2522,2523,3862,3863（0始まり）。
当該ログのspawn-name-diagnostics.jsonとsession-analysis-name-diagnostics-review.jsonへ保存した。
元ログSHA-256と統合会話10群の生成本文は不変。警告6件を消したのではなく、原因と未確定部分を可視化した。
World・GUI・group/titleの関連22項目を選択して確認。全件テストやAuriga実行は行っていない。
