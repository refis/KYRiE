## 通常一覧と装備一覧に重複する弾薬（2026-10-28）

20261028-012526-0abe69d9の3スナップショットで、同じIndex・ItemID・type=10が
0B09の数量付き一覧と0B39の数量欄を持たない装備一覧へ重複していた。
通常一覧の受信数量601／579を保持し、装備一覧の仮の1で上書き・加算しない。
開始／終了で囲まれた同じ接続の一覧で、IDとtype=10が一致し、
一方が通常一覧（0B09/0B38）、他方が装備一覧（0B0A/0B39）の場合だけ統合する。
順序はどちらでもよい。全件完了時にtype=10の装備情報しかない場合は、数量を補わず拒否する。
開始未観測、同じ一覧種別の二重送信、三重重複、ItemID・種別の不一致は従来どおり拒否する。
一覧統合後の枠数に上限を適用し、失敗時は既存所持品を変えず全件状態を解除する。

session-analysis-inventory-review.jsonでは所持品の問題34件が0件となり、
通常一覧で観測した数量から後続07FAを減算できる。会話問題は1件、生成エラー0件。
元ログ・以前の解析結果は比較用に保持した。参考イベントスクリプトからの数量補完は行っていない。

主画面の基本データ欄にマップ、XY、所持品の枠数／合計個数、Zenyと前回比を表示する。
[NPC・MOB配置のマップ補完](entity-map-context.md)にも、同じプレイヤーマップ判定を利用する。
「基本データ…」は別ウィンドウでIndex・ItemID・数量を確認し、基本データ全体をJSON保存する。
「選択接続の所持品」と「キャラクター台帳」をタブで切り替える。
アイテム名の辞書はまだないため、名称を推測せずItemIDを表示する。
HP/SPも受信していればJSONへ保持する。
[キャラクター一覧・ログイン情報](login-character-data.md)から名前・BaseExp・JobExp・Zenyも保存し、
一致するaccount/characterの現在状態へ反映する。キャラクター台帳は基本データJSONのcharactersを参照。

複数の接続があると選択欄が現れる。既定は新しく観測した接続。
手動で接続を選んだ後は選択を維持する。違う接続・再接続・取得世代の値は合算しない。
現在の接続でZenyが未取得なら「不明」。別接続の値を自動的に現在残高へ移さない。
再取得・明示的なマップログインでは基本データを再収集する。

## 位置の根拠

- 0091/0092: マップ名と移動先XY。
- 02EB/0A18: マップ入場時に受信した圧縮座標。
- 0087: 歩行の出発点と目的地。GUIには矢印と「到着未確認」を付ける。
  通信だけで歩行途中の実座標や到着を確定しない。
- 0088: 補正対象IDが0283またはSENDのマップログインで確認した自分のIDに一致する場合だけ更新。
  他NPC/MOBの補正でプレイヤー位置を変えない。
- 0071の移動先マップ名は、同一取得内のSEND 0072/0436にあるCharacterIDが
  一致した場合にだけ新接続へ関連付ける。SEND未取得なら初期マップは不明になり得る。

## 所持品

- 0B08(type=0)開始 → 0B09/0B0A/0B38/0B39の分割一覧 → 0B0B(type=0, flag=0)終了を受信したら全件として確定。
- MARiAにある1件のサイズ34/67/35/68バイト、5バイトの一覧ヘッダーを使用する。
  対象バージョンに依存し、サイズが合わなければ黙って読み替えない。
- 枠数はIndex数、合計個数は各Indexの数量合計。装備品は1枠1個。
  同じItemIDでも別Indexは別枠として数える。
- 途中で取得した一覧／差分は「部分観測」。全件取得中は「更新中」。
  未観測の所持品を0個と断定しない。空の全件一覧は0枠と表示できる。
- 倉庫・カート等のtypeは所持品に混ぜない。
- 0A37/0B41は成功result=0の取得だけを加算する。
- 00AF/07FAは観測済みIndexから減算する。未知Index、数量不足、IDの衝突、重複一覧、
  不正サイズ、上限超過では内容を捏造せず全件状態を解除し、根拠付きの問題を残す。
- 全件受信後の差分が正しく読めれば、そのまま全件状態を維持する。
- 1接続4096枠、接続64件、マップ引継ぎ候補16件、直近の問題100件で保持量を制限する。
  全ゲームバージョンの消費・取引・倉庫移動パケットを網羅したものではない。

### 一覧ストライドと鑑定フラグの検証境界（#48）

通常shopの商品行（00C6=13byte／0B77=19byte）とは別経路。ここは所持品一覧のみ。
Issue表記の「35／68byte」は 0B38／0B39 のレコード長を指す。未検証長への自動切替はしない。

| PacketID | 種別 | レコード長 | 鑑定フラグ | 状態 |
|----------|------|------------|------------|------|
| 0x0B09 | 通常一覧 | 34 | offset 33 の bit0 | 確認済み |
| 0x0B0A | 装備一覧 | 67 | offset 66 の bit0 | 確認済み |
| 0x0B39 | 装備一覧 | 68 | offset 67 の bit0（offset 66 は grade） | 確認済み |
| 0x0B38 | （旧）通常一覧 | MARiA想定 35 | 位置未確認 | **PacketLength 未登録**／現行採取 0 件。利用廃止の可能性 |

根拠: ローカル Auriga `clif.c` の 0B09／0B0A、[rAthena NORMALITEM_INFO／EQUIPITEM_INFO](https://github.com/rathena/rathena/blob/master/src/map/packets_struct.hpp)、
既存実ログ末尾照合（0B39）。

**0x0B38**: ワークスペース `PacketLength.txt` に ID 行がなく（0B37 の次は 0B39）、フレーミング定義もない。
未知 ID として当該ストリームを閉じる。長さやフラグ位置を推測して追加しない。
MARiA は 35byte 行を読む互換コードを持つが、鑑定フラグ根拠はない。
実ログでも未観測のため、追加採取の優先対象から外す（[採取リスト I01](../capture/raw-packet-collection-checklist.md#i01-0b38所持品一覧採取優先から外す)）。
合成／手渡しの PacketEvent 向けに `LIST_STRIDES` へ 35 を残すが、`IDENTIFY_FLAG_OFFSETS` には載せない
（`identified=None`）。0B09 実例を 0B38 検証済みへ流用しない。

## ログの外部書式

config/auriga/display.jsonを73 IDから93 IDへ拡充した。
config/receive_display.jsonは従来の互換ファイル、rAthenaは従来の低優先度プロファイルを維持する。

- 09FE/09FF/09FD: NPC/MOBの初回観測・出現・待機・移動。名前、外見、ID、速度、
  オプション、座標と目的地を表示する。最初のidle/moveは「初回観測」として、実際のspawnとは区別する。
- 名前だけがcp932として読めない場合は数値情報を保持し、「名前解読不可」を添える。
- 0071/0283/02EB/0A18/0087/0088: マップ・自己ID・位置の観測。
- 00B0/00B1/0ACB: 基本ステータス。type=20はZeny、type=1/2はBaseExp/JobExpの絶対値。
  初回値（ログイン／キャラ一覧反映含む）は収入として扱わず「差分不明」と表示する。
  既知のZeny差分は `set Zeny,Zeny{delta:+d};`。BaseExp/JobExpの既知増加（00B0系）と
  経験値通知（0ACC）は観測ログへ `getexp` を出さず、会話紐づけの資源観測＋採用時のみ
  `getexp` 化する（戦闘EXPのログ洪水を避ける）。差分0は抑制、EXP減少はコメントのみ。
- アイテム取得／減少と一覧の開始・分割・完了を表示する。
  属性なしで鑑定済みの取得はgetitem、観測済みIndexからの減少はdelitemの書式。
  精錬、カード、オプション、期限、バインド、未鑑定等は@item_gainに属性を残す。
  取得失敗はresultを表示し、所持数を増やさない。

追加した任意キーdecoderは固定のactor/playerだけを許可する。
プロトコル解析はreconstruction側、文面と条件付き書式はJSONのtemplate/variantsで管理する。
式や任意コードは実行しない。書式再読込・時刻表示切替ではGUIの基本データを再計算しない。
表示用の独立した状態だけをログ順に再構築する。

## 再解析と検証

```powershell
python -m tools.analyze_player logs/SESSION/capture.jsonl --definitions client/PacketLength.extracted.txt --output logs/SESSION/player-observations.json
```

出力は接続別の基本値、Index別所持品、各更新のパケット番号・時刻・接続、TCP再生診断。
元のログ、長さ定義、SQLite列は変更しない。

Zenyは別の途中取得接続で観測され、新しい接続では未取得。識別がないので残高を引き継いでいない。

旧ログの出現情報に名前解読不可が2件あり、座標などの数値は表示する。
