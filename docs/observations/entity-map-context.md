# プレイヤー現在マップによるNPC・MOBの配置補完

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

## インスタンスモード（2026-10-28）

観測MAP名に`@`が含まれる場合はインスタンスモードとする。名前は観測値を保持し、
元MAP名への置換やインスタンス番号の除去は推測で行わない。
インスタンス内からインスタンスMAPへのwarp候補は`getmdmapname("観測MAP名")`を使う。
通常MAPからインスタンスMAPへの移動はmdenter内の移動の可能性があるため、warp全体をコメント化する。
移動元が未取得の場合も確認用コメントとして残す。通常MAPへの退出warpは文字列参照のまま。
同一会話内の連続warpは、直前に観測した移動先を次の移動元として保持する。

インスタンス中のNPC名引数は`getmdnpcname`を使用する。現在の生成対象ではcallshopが該当する。
NPC・shopの宣言名やコメントの名称は関数呼出しへ変換しない。
Aurigaの関数構文はローカルscript_ref.txtとbuildin_md.c/buildin_npc.cで照合済み。
実行先の元MAP名・NPC名への対応やmdenter呼出し自体は補完せず、Auriga本体の動作確認は別途必要。

個体出現パケットにマップ名は含まれないため、WorldStoreのNPC・MOB配置には
同じ取得世代・通信フローで判明したプレイヤー現在マップを用いる。
GUIで選択中の別接続や、全接続のうち最後に見たマップを一律に割り当てる処理ではない。

従来の0091/0092のマップ移動通知に加え、PlayerStoreと同じ判定を利用して
0071の選択キャラクターのマップ情報を、0072/0436のキャラクターIDが一致するログイン先へ引き継ぐ。
SEND/RECVでconnection表記が違っても、同じflow_idであれば現在マップを参照できる。
0092後のサーバー切替でも、キャラクターIDに対応したマップを新しいログイン先へ渡す。
別キャラクター・別フロー・別取得世代へ無条件に値を持ち越さない。
accountが取得できた情報はaccountも照合する。未識別の同一character IDが複数フローにある場合は
補完せず、再ログイン後の旧フローの移動先も次の接続へ引き継がない。

WorldStore内ではマップ関連のパケットだけをPlayerStoreへ渡し、所持品・戦闘情報を二重に保持しない。
状態は最大64フロー、キャラクターのマップ情報は最大16件。取得切替で消去する。
不正なマップ関連パケットから補完せず、解析問題として記録する。

## 根拠と出力先

配置のmap_nameに加え、map_origin=player_current_mapとmap_evidenceを保持する。
map_evidenceには通信フロー、補完したマップ名、ログイン／移動通知のパケット番号等を記録し、
キャラクター情報からの補完では対応するマップ情報の参照も残す。
個体出現そのものがマップ名を通知したとは扱わない。

NPC/MOB一覧、会話のNPC情報、ショップのNPC情報、MOB配置・再観測、配置編集用候補へ反映される。
既存ログ・プロジェクトの再読込でも、共通のWorldStoreを通して同じ結果を構築する。
古い解析済みJSONは変更しないため、元ログを再解析して新しい結果を保存する。
マップが判明した会話は、既存の配置一致条件に従ってログ間統合の対象にもなり得る。

取得開始時にプレイヤーのマップが未取得なら不明のまま。
後のマップ移動先を過去の個体へ遡って割り当てず、前マップの個体も従来通り別世代に残す。
補完は初回出現時の現在マップを使い、過去の記録全体の書換えは行わない。
