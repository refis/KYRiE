# 作業プロジェクトの保存・再開

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

1件または複数件の生ログから再解析した作業設定を `.gpa.json` に保存できる。
パケット本文や解析オブジェクトはプロジェクトへ複製せず、再開時に元ログから再構築する。
ライブ取得の履歴・DBを保存／再開する機能ではない。

## 操作

1. 観測を停止し「生ログを開く…」または「作業 → 複数の生ログを開く…」から別ウィンドウへ読み戻す。
2. 再解析完了後、そのウィンドウの「作業 → 作業注記…」で観測条件等を記入できる。
3. 「作業 → プロジェクトを保存…」で `.gpa.json` を保存する。
4. 次回は元画面の停止中に「作業 → プロジェクトを開く…」を選択する。

再開は別ウィンドウで行い、元画面の履歴は変更しない。
読込中・失敗状態では作業保存を有効にしない。
既存のコード候補・会話JSON保存は、プロジェクト保存とは独立して利用できる。

## 保存するもの

- ログ、長さ定義、RECV/SEND表示JSON、同梱のAuriga会話書式JSONへの絶対パスとSHA256。
- PacketIDフィルター、タイムスタンプ表示、未定義表示、選択タブ・会話、統合表示の状態。
- 作業注記（最大8192文字）。注記は利用者が記録した情報であり解析器の因果判定には使わない。

同じソフトウェア版で作業を再開するための設定ファイルであり、完全な環境アーカイブではない。
辞書や解析器の全ソース、ウィンドウの位置、パケット表の行選択は保存しない。
相対パスへの移行は未対応。移動した参照先は次の修復操作で選び直せる。
複数ログの読み戻しは[比較ガイド](multiple-log-replay.md)を参照。
会話書式は現在使用する同梱 `config/auriga/dialogue.json` のみを参照する。

## 変更検出と入力保護

再開時に参照先の有無とハッシュを確認する。内容が変わっていた場合、
変更後の設定で黙って結果を置き換えず再開を止める。
必要なら元ファイルを復元するか、生ログから新しく開いて作業設定を作り直す。
通常の読み戻しでも、処理前後の生ログハッシュが異なる場合は結果を公開しない。
ハッシュ一致はパケット定義の正しさやソフトウェア版の一致を保証するものではない。

保存時にもログと解析済み内容の一致、長さ定義と使用中の表示書式の一致を確認する。
書式を外部編集した場合は再読込してから保存する。
プロジェクトをログや参照設定と同じパスへ保存する操作は拒否する。
保存は同じディレクトリの一時ファイルから置換し、保存失敗で既存の作業ファイルを壊さない。

プロジェクトJSONは1MiB、参照する設定ファイルは各2MiBが上限。
重複キー、未対応schema、不正な設定型・参照情報は拒否する。
ログのハッシュ確認・再解析はワーカーで実行する。設定ファイルの確認と作業保存時の
ハッシュ確認は現在GUIスレッドで行うため、大きなファイルや低速ストレージでは待ちが発生しうる。
生ログのGUI再生上限・取消の動作は[読み戻しガイド](offline-replay.md)を参照。

## 複数ログ用の形式と互換性

1ログの保存は従来どおりschema=1。複数ログはschema=2とし、既存形式も引き続き開ける。
schema=2のfilesは共通のRECV/SEND表示JSONと会話書式を保持する。
sourcesに各ログ・各長さ定義の参照とハッシュ、取得世代番号を保存する。
ログ順と世代番号を再開時にも維持する。コピー重複の除外で番号に欠番があっても詰め直さない。
保存するのは採用されたログのみであり、除外したコピーの一覧は再開後の診断へ引き継がない。

最大20ログ、取得世代は重複のない昇順1～20。
空のsources、不正なハッシュ、同じ内容のログの重複、世代の重複・逆順は拒否する。
どれか1件のログや定義が変更・欠落していたら、全体の再開を停止する。
先に読めたログだけを完成結果として公開しない。入力への上書き禁止・一時ファイルからの保存も共通。

全216テスト通過。既存テストを拡張し、schema=1互換、schema=2の保存・再開、
欠番維持、統合コード・注記・出典の一致、後半ログと定義の変更検出、不正形式と入力保護を確認した。
既存実ログ2件でも1754パケットを保存・再開し、件数・出典・統合本文・注記が一致した。

## 移動したファイルの参照を修復する

停止中の元画面で「作業 → プロジェクトの参照先を修復…」から `.gpa.json` を選択する。
一覧で修復対象の行を選び、「選択した参照先を変更…」で移動先を指定する。
保存時のSHA256と一致するファイルだけを受け付ける。内容が異なる新版の定義や表示書式へ
差し替える機能ではない。その場合は生ログから新しい作業を作る。

同じパス・ハッシュを共有する参照はまとめて更新する。ログの順序、取得世代の欠番、
表示設定・注記・保存したハッシュは変更しない。会話書式は現在の同梱ファイルへ接続する。
状態の「未検証」は存在確認のみ。「一致確認済み」は選択時に内容を確認したことを示す。
保存前に全参照を再検証するため、未修復の欠落や選択後の変更があれば保存しない。

「修復したプロジェクトを保存…」で別名保存し、そのファイルを作業メニューから開く。
元プロジェクト・生ログ・設定ファイルは自動更新せず、閉じる／ファイル選択取消でも維持する。
入力ログや参照設定への上書きは拒否する。元プロジェクトへの保存は利用者が明示選択した場合のみ。
再解析後の出典パスは移動先になる。内容と取得世代は維持するが、出典パスを含む内部識別や
並び順に依存する候補番号まで不変とは保証しない。

修復時のハッシュ確認は現在GUIスレッドで行うため、大きいログや低速媒体では待ちが発生しうる。
自動探索は未対応。内容差替え・ログ一覧編集は次節。
schema=1/2に対応し、ファイル数・サイズと保存上限は既存プロジェクトと同じ。

## ログの追加・削除・並べ替え・内容差替え

停止中の元画面で「作業 → プロジェクトのログ一覧を編集…」から `.gpa.json` を選ぶ。
schema=1は編集時にschema=2へ変換し、既存ログを世代1として扱う。

- **追加**: 生ログと長さ定義を選び sources へ追加。同じ内容（SHA256）の重複は拒否。取得世代は未使用の番号。
- **削除**: 選択行を削除。残り1件は削除不可。残りの世代番号は詰めず欠番を維持する。
- **並べ替え**: 一覧上で上下移動。並び替え後の世代は 1..N へ付け直す。旧世代へ紐づく根拠は無効になるため、保存後に開き直して再解析する。
- **内容差替え**: 参照修復とは別操作。別内容の生ログ（任意で長さ定義）へ差し替え、保存ハッシュを更新する。
  同一内容の移動は拒否し、修復画面へ誘導する。差替え後は古い根拠移動を使わず、プロジェクトを開き直す。

「編集したプロジェクトを保存…」は既定で別名保存。入力ログへの上書きは拒否する。
ライブ取得ウィンドウの履歴は変更しない。編集中のオフライン結果をその場で再公開しない。

全217テスト通過。異なる内容の拒否、元作業の保護、共有定義の更新、修復後の再解析を確認した。
組合せ試験で発見したNamed PipeテストのQt遅延解放も整理し、実行順序を変えたGUI連携を確認した。


## 名称辞書の参照と版照合（2026-10-30）

新しいGUI保存では、使用中のスキル名・スキルユニット名・状態／効果名の辞書を
catalogs欄へパスとSHA-256で記録する。標準書式では3辞書が対象。
独自の表示書式がユニット／状態・効果のdecoderを使用しない場合、その表示辞書は含めない。
スキル名はMOB画面が読み込んだ内容のハッシュ、表示辞書はDisplayProfileが固定したハッシュを使う。
ディスク上の内容と画面が保持する内容が異なる場合は、既存のプロジェクトを上書きせず保存を拒否する。

再読込は参照ファイルの有無・内容に加え、実際に使う現在の同梱辞書も保存時と照合する。
再解析前後の照合と、画面への公開前に読み込み済み辞書を確認し、異版で結果を表示しない。
辞書ファイルを読み込めなかったMOB画面の未確定状態も保存の根拠にしない。
同じ内容の参照先移動は従来の修復画面で扱えるが、別内容の辞書への差替えは不可。
修復先のファイルだけでなく、現在のconfig内辞書も保存時と同じ内容である必要がある。
任意パスの辞書を直接実行時へ差し込む機能や、辞書本体のプロジェクト同梱は今回の対象外。

辞書を更新して以前のプロジェクトが開けなくなった場合は、保存時の同梱辞書を復元するか、
生ログを新規に開き、現在の辞書で再解析して別の作業として保存する。
同じ表示を維持する必要がある作業では、更新前の辞書も別途保管する。
生パケット・PacketID・長さ定義・会話の数値引数を辞書名で置き換える変更ではない。

catalogsを持たない従来のschema1/2は引き続き読める。
この場合はウィンドウ名に「名称辞書版未記録」と表示し、保存時の名称まで再現できたとは扱わない。
現在のGUIで保存し直すと読み込み済み辞書の参照が加わる。
catalogsは現行作業版の追加項目であり、過去のアプリが新しい保存ファイルを読める保証ではない。

対象9テストで単一／複数保存、同内容移動、欠落・変更・使用版相違、保存失敗時の元ファイル保持、
公開前照合、旧形式、参照修復とスキル名再読込を確認した。全件テストは実行していない。
現行6タブに合わせ、パケット詳細（index5）選択時の作業保存も可能にした。
実ログ20261029-215033-0a6328faのcatalog-pinned-work.gpa.jsonは3辞書付きの確認用プロジェクト。
ログと全参照のハッシュ照合を確認したもので、移設環境やAuriga実行の検証ではない。


品名・MAP・クエスト名の追加後はclient_namesも名称参照へ含め、標準書式では4辞書になる。
従来の3辞書付き作業は開けるが、新たな品名等の表示版は保証できないため「名称辞書版一部未記録」と表示する。
元データの照合は維持し、新規保存では現在使用中の4辞書を記録する。

ナビ資料の追加後はnavigationも固定対象へ加わり、新規保存は標準5辞書になる。
約2.8MBのnavigation.jsonのみ4MiB上限。既存の設定・名称辞書は2MiB上限を維持する。
以前の3/4辞書付き作業は「名称辞書版一部未記録」を表示し、保存し直すと現在の5辞書を記録する。
