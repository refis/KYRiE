# 複数ログのGUI比較

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

観測停止中に「作業 → 複数の生ログを開く…」で複数のcapture.jsonlを選択する。
別ウィンドウで各ログを個別にTCP再構成し、NPC/MOB・会話・基本データをまとめて確認できる。
会話画面の「同一NPCの観測経路を統合」を有効にすると、既存の識別・品質条件を満たす会話を統合する。
単にNPC名やActorIDが同じだけではログをまたいで統合しない。

## ログと定義の分離

- 各ログを選択順に別の取得世代へ割り当て、source_sessionsへ出典の絶対パスを記録する。
- TCP再構成器はログごとに新規作成する。同じTCP番号・ActorIDでも接続や個体を混ぜない。
- 各ログの横のPacketLength.used.txtを優先する。なければ元画面の選択定義を使う。
- 画面設定の定義欄は最初のログのもの。全ログの定義パス・ハッシュ・診断は診断レポートのsourcesを参照。
- 表示書式は共通。履歴を並べる際に表示状態を取得世代ごとにリセットする。
- ログ間の時計を同期したり、異なるログのイベントを1本の時系列として因果付けたりしない。
  表示順はログ選択順・各ログの取得順であり、全ログの絶対時刻順ではない。

同じ絶対パスの重複選択は1回だけ読む。
内容ハッシュが同じコピーも、同じ長さ定義なら重複として除外して試行数に加算しない。
同じ内容に異なる長さ定義が付いていた場合は、二重試行として扱わず読込全体を停止する。
除外したコピーは診断のduplicate_logsに残す。内容が異なる再保存ログの同一性は判定しない。

## 失敗・取消・保存

ファイル数は最大20、入力サイズは合計128MiB、完全パケットは合計2万件、
パケット生データは合計32MiBまで。各ログの行数・行サイズにも1ログ読み戻しと同じ制限を適用する。
1件でも形式不正・上限・読取失敗があれば、先に読み取ったログも完成結果として公開しない。
取消でも元画面を維持する。未知IDによる接続停止は失敗を隠さず、完全なパケットと診断を残す。

会話のコード保存・統合JSON保存、NPC/MOBの根拠付きJSON保存を使える。
複数ログも「作業 → プロジェクトを保存…」から保存・再開できる。
形式と変更検出は[プロジェクトガイド](offline-project.md)を参照。
1ログだけを選んだ場合は従来の読み戻しとして開き、作業プロジェクト保存も使える。
GUI内でログを後から追加・削除・並べ替える機能も未対応。変更時は別ウィンドウで開き直す。

## 検証

全216テスト通過。合成した別ログの選択1・2が1候補になることとCLI一致を確認した。
出典・取得世代の分離、コピーの重複除外、後続ログの不正で部分結果を公開しないこと、
同一ログに異なる定義を与えた場合の停止、既存1ログの作業保存・再開も確認。

実ログ20261026-223425-131e9688と20261027-064450-e05d0fb7を同じ抽出定義で読み戻し、
1754パケット・会話2件・統合候補1件・識別不足による除外1件がCLIと一致した。
この実ログ2件の別分岐統合が成立したという意味ではない。分岐統合の検証は合成ログによるもの。
日本語のオフスクリーン画面も確認した。新しい実ゲーム取得との併用は未検証。
