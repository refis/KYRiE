# 保存ログのGUI読み戻し

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

観測を停止してから、主画面の「生ログを開く…」で `capture.jsonl` を選ぶ。
別ウィンドウに観測ログ・基本データ・NPC/MOB・会話と根拠を再構築する。
元の観測画面の履歴とpackets.sqlite3は変更しない。
再解析側は専用メモリDBを使い、ライブ取得は開始できない。
[複数ファイルの比較](multiple-log-replay.md)は「作業」メニューから開く。
1件・複数件とも[プロジェクト保存・再開](offline-project.md)に対応する。

## 定義と表示書式

ログと同じフォルダの `PacketLength.used.txt` があれば使用する。
なければ元画面の設定で選択している長さ定義を使用する。
別の定義候補を使う場合は、元ログを変更せず、候補定義と再解析用コピーを別フォルダへ置く。
使用した定義は設定欄で確認でき、診断には定義ハッシュとCLIと同じ再生レポートを表示する。
これは記録当時のクライアント版との適合を自動保証するものではない。
表示書式は元画面で選んだRECV/SENDの設定を引き継ぐ。再解析側でも書式変更・再表示が可能。

再解析には「再解析用の生バイトを記録する」を有効にして取得したログが必要。
本文を記録していない診断ログやSQLiteだけからTCPを再構成する機能ではない。
schema 1のTCPセグメント形式と旧stream_chunk形式を、CLIと同じ処理で読み取る。

## 進捗・取消とエラー

読取・TCP再構成はワーカーで実行し、完成したパケット群だけをGUIへ渡す。
意味解析・画面追加は100パケット単位でイベントループへ戻しながら実行する。
「取消」は再解析ウィンドウを閉じ、元画面を残す。ワーカー終了後に解放する。
ファイル読取・形式不正・上限で失敗した場合は、読取途中のパケットを公開しない。
画面構築中の失敗は「未完成」と表示し、その結果を完成した観測として扱わない。

未知IDやTCP欠損は従来どおり接続ごとに停止し、完全なパケットと診断を表示する。
停止接続数、未処理ストリーム、記録終端の有無は診断レポートを確認する。
「再解析完了」は読取処理の完了であり、全通信に欠損がないことを意味しない。
記録終端がない場合は主画面にも明示する。未知IDの飛ばし・再同期は行わない。
不正レコードの値や本文をエラーメッセージに含めない。

GUI再生の既定上限は入力ファイル128MiB、1行2Mi文字、約20万行、
完全パケット2万件、パケット生データ合計32MiB。
本文以外にオブジェクトやGUIのメモリも増えるため、既定は低く置く。
パケット件数とRAW合計は「設定 → 記録」のローカル設定（`config/user_settings.json`）で
1000〜200000件／8〜256MiBの範囲で変更できる。超過時は部分結果を成功扱いしない。
GUIが重い・上限を上げたくない場合はCLIで観測JSONへ変換する。

```powershell
python -m tools.analyze_session logs\SESSION\capture.jsonl --definitions PacketLength.txt --output logs\SESSION\session-analysis.json
```

長さ定義はログ横の`PacketLength.used.txt`があればそれを優先して指定する。
ページング、DBからの遅延表示は今後の最適化対象。

## 保存と検証

従来の表示保存・会話JSON・NPC/MOB観測・コード候補保存を利用できる。
source_sessionsには入力ログの絶対パスを保持し、根拠パケットへ戻れる。
閉じるとメモリDBと再解析履歴は失われるため、必要な候補・根拠は保存する。
1ログの作業設定は[作業プロジェクト](offline-project.md)として保存・再開できる。
複数ログのGUI統合は[複数ログ比較](multiple-log-replay.md)を参照。

全212テスト通過。合成双方向ログのCLI一致、元履歴／DB保護、取消、
不正入力、上限、未知ID停止の報告を確認。
実ログ `20261027-064450-e05d0fb7` は1222パケット・会話1件をGUIへ再構築し、
送受信のID別件数と会話本文がCLIと一致した。オフスクリーンで日本語画面も確認した。
新しいWindows実機でのライブ取得との併用確認は未実施。
