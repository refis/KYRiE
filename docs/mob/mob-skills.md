# MOB使用スキルの観測

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

全スキル観測JSONは最大64MiB。元ログとconfig以下への上書きを拒否し、
一時ファイルへの書込み完了後に保存先を置換する。失敗時は既存ファイルを保持する。
不正な非有限数の出力は拒否する。手動設定JSON・DB候補出力にはそれぞれの保存制限を適用する。

## 通知一覧と表示上限（v0.0.4保存後の開発）

使用スキルの行を選択し、下側の「通知一覧」を開く。
取得世代・MAP世代・ActorID・視界区間、通知種別、対象ID／地点、レベル、通知値、品質を表示する。
行を選ぶと元の記録JSONを確認でき、「通知の根拠パケット」で実際の通知へ移動する。
「選択個体」の絞り込みにも追従し、選択解除後は古い通知への移動を無効にする。

レベルを含まない通知は「未通知」、値が0や未確定表現の場合はraw値付きの「不明」、
解析で観測できた有効レベルは数値で表示する。詠唱開始にレベルを補わない。
対象IDがあっても未分類なら「他対象（未分類）」とし、プレイヤー等へ推測分類しない。
通知値のdamage、delay、tickやeffect_valueは受信したフィールドであり、基本ATK・設定ASPDや
スキル使用回数・クールダウンへ自動変換しない。

通知一覧と概要の通知本文JSONは末尾1000件まで表示し、保持件数と画面の省略件数を明記する。
既存の保持上限・統計・詠唱候補・間隔・全スキル観測JSON・DB候補は変更しない。
全件は「保存… → 全スキル観測JSON…」で確認する。名前辞書の再読込や一覧更新後も、
同じ通知が表示範囲に残っていれば選択を維持する。
床アイテム履歴・ドロップ一覧はこの機能の対象外で、保存データの追加収集は行わない。

## HP割合とスキル通知の並列確認

「通知一覧」の各行に、直前のHP割合通知（0A36、5%刻み）・取得時刻差msを表示する。
「割合通知の根拠」で割合側、「通知の根拠パケット」でスキル側へそれぞれ移動できる。
同じ取得・接続・MAP世代・ActorID・視界区間・クラスの、受信順で先行する割合通知だけを参照する。
実数HP／最大HPから割合を計算せず、未来の割合を遡って使用しない。

上部で割合を手入力し「通知値が以下」「通知値が以上」を選ぶと、各行に通知値との比較結果を表示する。
これは5%刻みの過去の通知値との比較であり、正確な現在HPやスキル条件成立の判定ではない。
0%表示だけで死亡を確定しない。取得差が大きい場合も値を補間せず、その時刻差を見て判断する。
詠唱開始と攻撃／効果通知は異なる時点なので、後者の割合を使用開始判定時のHPとは扱わない。

未取得、不正割合（例: 0xFF）、時刻逆行、品質注意、途中取得等は比較を「未判定」とする。
新しい不明通知を古い有効値で置き換えない。classが別の値を経由して元へ戻っても、変更後に
割合を観測するまで再利用しない。class変更履歴の保持欠落も要確認として扱う。
元のスキル・性能JSON、統計、DB候補は変更せず、CONDITIONやCONDITION_VALUEは手動指定を維持する。
画面の参照情報は既存の性能記録から導出し、追加のHP履歴ファイルは収集しない。

## 詠唱通知と後続の対応候補（2026-10-28）

使用スキルの行を選び「詠唱の対応候補」を開く。
個体・対象ID・詠唱通知のms・後続通知までの取得時刻差・観測状態と両端Packetを表示する。
詠唱開始と後続通知それぞれの根拠へ移動できる。後続未観測の行では後続側の移動を無効にする。
品質フラグがある場合は要確認とし、完全な個体キー・フラグはツールチップへ保持する。

このビューは既存SkillStoreのlinked_cast_indexを読むだけで、新しい関連付けを推測しない。
個体・クラス・スキル・取得世代が異なるリンクは採用しない。
取消通知も対応候補として表示し、キャンセル可能設定や成功・失敗を確定しない。
通知のcast_msと取得時間差を区別し、実詠唱時間やDBのCASTTIMEへ自動代入しない。
総合解析JSONのskill_cast_reviewにも同じ情報を保存し、association_confirmed=falseを維持する。

tracking_endには、追跡を終えた理由と、その状態を確認したPacketを保持する。
消滅・死亡通知、マップ移動、クラス変更、次の詠唱、解析停止、記録上限を区別する。
GUIの「追跡終了の確認パケット」から確認できる。取得世代変更だけでパケットが特定できない場合は
番号を補わず、このボタンを無効にする。
死亡通知で追跡を終えたことは、スキルが取り消された原因や成否を確定するものではない。
記録上限で取消通知を保持できなかった場合も取消済みとせず、上限到達として記録する。

追加ログで追跡終了としていた2件は、Packet 10675・10694の死亡通知を確認した時点で終了していた。
後続未観測と追跡終了を分けて保持し、CASTTIME・キャンセル設定へは転用しない。
全308テスト通過。参考イベントスクリプトからの補完は行っていない。

## 効果通知の取得時刻差（2026-10-28）

011A/09CBにはサーバーtickがないため、capture_effect_notificationとして取得時刻差を別に保持する。
同じ出現記録・クラス・スキル・対象ID・結果値の通知間だけで計算する。
対象0、同時刻、時刻逆行、途中取得など不確かな端点では比較値を出さない。
間隔ごとに先頭／末尾Packet番号、個体キー、対象ID、結果値を保持し、個体内で計算してから集計する。
GUIのスキル詳細に「効果通知の取得時刻差（同じ対象・結果）」として表示する。

「使用スキル」で行を選び、下側の「間隔の根拠」タブを開くと、
詠唱開始・ダメージtick・地点tick・効果通知の全比較区間を確認できる。
取得世代／ActorID／出現記録、対象ID・結果（効果通知の場合）、時間差、両端のPacket番号を表示する。
行を選んで「比較開始の根拠」「比較終了の根拠」を押すとパケット詳細へ移動する。
ダブルクリックは終了側へ移動する。完全な接続・マップ世代を含む個体キーはツールチップでも確認できる。
比較区間のないスキルへ切り替えると選択を解除し、古い根拠へ移動しない。
この操作で元のスキル統計・観測・DB候補は変更しない。

これは通知間の差であり、継続効果や複数通知を含む可能性がある。
スキル使用回数・設定ディレイ・確率・条件へ変換しない。DB候補のDELAYは未確定のまま保持する。
新系列も観測根拠の一部になるため、以前保存した手動設定JSONの根拠が再解析結果と異なる場合は
自動移行せず、既存の一致検証で拒否する。新しい根拠を確認して設定を再作成する。

20261028-012526-0abe69d9では90通知・21クラス／スキル組、解析問題0。
この系列の比較は15件・2組（2988/354と2992/135）であり、配置数や使用回数ではない。
mob-skills.jsonと全行コメントのmob-skill-review.txtへ保存した。
参考のイベントスクリプトから時刻や条件を転用していない。全304テスト通過。

「MOB」タブ下側の「使用スキル」を開く。
「クラス別（全観測）」は全記録の集計、「選択個体」は上側で選んだ出現記録だけを表示する。
スキル行を選ぶと、間隔の根拠、詠唱通知値、レベル、対象、パケットJSONを確認できる。
「根拠パケット」で選択スキルの最後の通知へ移動する。
「保存… → 全スキル観測JSON…」は全記録を出力する。表示中の行だけの保存ではない。
[Auriga DB編集用候補](mob-skill-export.md)も同じメニューから保存できる。

## 対応する通知

- 013E/07FB: 詠唱開始。スキル、対象、指定座標、通知された詠唱時間を保持する。
- 01B9: 詠唱中断。個体に未完の詠唱があれば関連付ける。なければ対応不明として別保存する。
- 01DE: ダメージ通知。スキル、対象、サーバーtick、レベル生値、分割数、
  ダメージ、送信元／対象ディレイ、表示タイプを保持する。
  ダメージとディレイの符号を保持する。負のダメージを正の攻撃力へ変換しない。
- 011A/09CB: 非ダメージ通知。効果値、対象、resultを保持する。
  効果値には回復量などが入り得るため、スキルレベルへ代入しない。
- 0117: 地点スキル通知。座標、tick、レベル生値を保持する。
- 09CAのユニット種別はスキルIDとは別なので、スキル辞書へ自動変換しない。

通知時点で、同じ取得世代・受信接続・マップ世代のアクティブな個体がMOBとして確認されている
場合だけ分類する。出現情報より前の通知、NPC／プレイヤー等の通知は遡ってMOBに割り当てない。
分類できない通知件数は別に数える。

## 使用回数・レベル・対象

詠唱開始、攻撃通知、その他通知、中断をそれぞれ数える。
攻撃通知数をスキルの使用回数と断定しない。同じ個体・スキルの同じtickは
複数対象への通知の可能性がある。同tickの連続通知を1組として保持するが、これも確定使用回数ではない。
一連の多段通知の自動統合や、全種類の通知にまたがる使用回数の推定は行わない。

レベル生値0と0x8000以上（0xFFFFを含む）は不明として残す。
MARiAのように不明値を分割数や非ダメージ効果値で置き換えない。
対象は自分、観測済みMOB、その他、地点、不明に分ける。
観測済みMOBへの効果だけで「味方」やAI条件とは判断しない。
移動情報は直近に観測した状態で、AIのattack／chaseモードを確定するものではない。

## 間隔と詠唱の関連付け

個体は取得世代・接続・マップ世代・ActorID・出現記録・その時点のクラスで区別する。
**個体内で間隔を計算した後にクラス別へ集約**する。
複数個体が交互に使っても、個体間の短い差を再使用間隔として混ぜない。
死亡・消滅後の再出現、マップ移動、再取得、クラス変更をまたいで計算しない。

以下は別系列で最小・中央値・最大・件数・from/toパケット番号を保存する。

- 詠唱開始の取得時刻差。
- ダメージ通知のサーバーtick差。
- 地点通知のサーバーtick差。

tickは32bitの周回に対応する。逆行または半周以上の曖昧な差は採用しない。
同tickは0ms間隔として集計しない。取得時刻の逆行、不正時刻、途中取得の系列も除外する。
問題のあった観測を端点とする次の間隔も除外し、以降の正常な系列で再開する。
全体の通信欠落・遅延の完全性は証明せず、transport_quality=not_verifiedを維持する。

詠唱と効果は同じ出現記録・クラス・スキルで、対象（地点ならXY）が整合し、
取得時刻差が非負かつ通知詠唱時間+1500ms以内の場合に関連候補として記録する。
これは通信で観測した対応候補で、サーバー内で同一の処理だった証明ではない。
通知詠唱時間と観測経過時間は分ける。中断、別の詠唱による置き換え、取得切替も記録する。
中断通知を見ただけで、そのスキルが一般にキャンセル可能とは断定しない。

最短観測間隔は設定された再使用ディレイではない。
発動確率・HP条件・射程・AI条件・元のATK/DEF、mob_skill_dbの確定行は生成しない。
攻撃通知・速度・HPの直接観測は[MOB性能観測](mob-performance.md)で整理する。

## 外部辞書と保存

config/skill_names.jsonに10進数ID→表示名を置き、「名前辞書を再読込」で変更できる。
`version`はスキーマ版、`skills`は名称マップ、`source`／`name_resolution`は出典メタとして分離する。
名称変更は集計やPacketIDを変えない。プロジェクト保存時のカタログSHAで版を照合する。
詳細は[mob_skill_db編集用候補](mob-skill-export.md#スキル名辞書の版と出典)を参照。
未登録IDは数値と未登録表示で保持する。不正辞書は直前の正常な辞書を維持する。

```powershell
python -m tools.analyze_skills logs/SESSION/capture.jsonl --definitions client/PacketLength.extracted.txt --output logs/SESSION/mob-skills.json
```

出力に個体別／クラス別集計、全スキル観測、根拠、分類不可件数、対応不明中断、TCP再生診断を保存する。
SQLiteの列、PacketLength、受信フレーミング、NPC会話解析は変更しない。
保持上限は100000観測、10000個体スキル組、直近の問題／対応不明中断100件。
上限では当該ワークスペースの追加観測を停止し、間隔の欠落を隠して集計を続けない。
上限到達後は保存してアプリを再起動する必要がある。

## 大量観測時の間隔表示・画面JSON

「間隔の根拠」は1ページ最大1000区間とし、初期表示は系列順の最終ページ。
「前の1000件」「次の1000件」で保持中の全区間を辿れる。根拠Packet番号は元の値を維持する。
過去ページを選んだ後は同じスキル・範囲の更新でもページを維持し、最終ページ選択時は最新ページへ追従する。
対象や表示範囲を解除した場合は一覧と根拠ボタンを消し、古い区間へ移動しない。

概要の画面JSONでは長い一覧（evidence、interval samples、通知本文等）を各末尾1000件まで表示し、
preview_omissionsに省略した一覧と件数を記載する。count・min・median・max等は全観測での集計値のまま。
これは表示用投影であり、元の全観測・全区間、統計、スキルJSON保存とDB候補のデータを削らない。

## 詠唱候補多数時のページ表示

「詠唱の対応候補」も1ページ最大1000候補とし、初期表示は観測順の最終ページ。
前後のページから、詠唱開始・後続・追跡終了の元Packetへ移動できる。
候補総数とページ数を表示し、過去ページは同じ対象範囲の更新でも維持する。
対象解除時は一覧と根拠ボタンを消す。全候補の対応情報、スキル統計、保存JSON、DB候補は変更しない。
通知までの時間差を実詠唱時間やCASTTIMEへ変換する処理も追加しない。


## 設置スキルユニットの名称（2026-10-30）

観測ログの0x09CAにユニット種別シンボル・参照スキル名を併記する。
原パケットは保持し、設置個体ID（offset4）、設置元ActorID（offset8）、ユニット種別（offset16）を区別する。
既存のactor_idフィールドは設置元として維持し、unit_actor_id/source_actor_idを追加した。
unit_idはスキルIDとは異なり、表示名からMOBの使用スキルやレベルを新たに集計しない。

config/skill_units.jsonはMARiA const.UNITIDと参照Auriga skill.h、skill_unit_db.txt、
クライアントSKID、現在のスキル名辞書を静的に照合した173種類の参照辞書。
共用種別は最大3名称と候補数を表示し、unit_skill_idsに全候補IDを保持する。
セイフティウォール型はスキル12と8033の共用であり、12を確定スキルとして採用しない。
種別264/265はMARiAとAurigaが不一致のため除外。未知値・除外値は数値を残して未登録と表示する。
未解決の対応6件は辞書内に記録し、列数不一致やシンボル／ID不一致を推測で修正しない。

unit_mapping_basisは定義の出典一致状況、unit_catalog_sha256は読み込んだ辞書の識別情報。
これは参照定義との対応であり、現サーバーでのAIや発動元の確定ではない。
表示書式を読み込むときに辞書も固定し、1パケットごとのファイル読込は行わない。
表示書式の再読込では更新した辞書を使用する。プロジェクト再解析でも辞書が変われば表示名は変わり得るので、
過去出力を再現する際は辞書とそのハッシュも保存する。プロジェクトへの辞書同梱は別の作業項目。

対応形式はRECV09CA、総長23byte。長さやヘッダーが一致しない場合は表示エラーとし、
不明な構造を推測して読まず、生ログ・ストリームは従来の取得処理に従って保持する。
旧ログ20261028-012526-0abe69d9では25件すべて名称解決・長さエラー0。
新ログ20261029-215033-0a6328faには対象通知なし。logs/skill-unit-label-review.jsonへ記録した。
関連10テストでID分離・共用・矛盾・未知値・静的解析・辞書固定・GUIとMOB集計不変を確認。
