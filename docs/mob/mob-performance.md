# MOB性能の直接観測

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

性能観測JSONは最大64MiB。元ログとconfig以下への上書きを拒否する。
UTF-8の一時ファイルへの書込み完了後に保存先を置換し、失敗時は既存ファイルを保持する。
不正な非有限数をJSONへ書き出さず、エラーを表示する。解析・キャプチャの動作は変更しない。

HP実数の取得を前提にせず、スキル条件の確認には[割合通知との並列表示](mob-skills.md)を利用できる。
5%刻みの通知値と時刻差だけを参照し、実数換算や条件閾値の推定は行わない。

## 個体別比較（v0.0.4保存後の開発）

性能観測のクラス行を選び、下側の「個体別比較」タブを開く。
同じクラスで保持中の個体別集計を、サーバーIP・PORT・ActorID順に表示する。
取得世代・MAP世代・ActorID・視界区間、与／被通知数、速度、最大HP通知、与被HPダメージ範囲、
最短HP tick差、品質フラグ付きレコード数を並べる。異常なHPを最大HPへ混ぜる等の補正はしない。

行を選ぶと集計値・品質フラグの内訳・根拠件数をJSONで確認できる。
「個体の最初の根拠」「個体の最後の根拠」は、保持中の性能観測レコードの両端へ移動する。
初出現パケットの完全保持や実体の生存期間全体を保証するものではない。
品質フラグ0件でも全件取得済み・正しい設定値とは扱わない。

同じActorIDでも視界区間・MAP世代・取得・接続を跨いで統合しない。
クラス別から「選択個体」へ切り替えると対象の区間だけとなり、選択解除時は古い根拠を消す。
更新後も同じ区間とクラスが残っていれば比較行の選択を維持する。
表示は最大1000区間で、保持中の集計件数と表示件数を明記する。全件の性能JSON保存は従来どおり利用できる。
既存の統計を読む表示であり、観測数を設定個体数へ、ダメージをATK/DEFへ、tick差を設定ディレイへ変換しない。
床アイテム履歴・ドロップ一覧は追加しない。

## 攻撃間隔の根拠を確認する（2026-10-28）

性能観測でクラスまたは個体の行を選び、下側の「攻撃間隔の根拠」タブを開く。
与HP／与SP、取得世代・ActorID・出現記録、相手ID・観測できた相手クラス、表示種別、
時間差と両端Packet番号を表示する。「比較開始の根拠」「比較終了の根拠」でそれぞれ移動できる。
ダブルクリックは終了側へ移動する。完全な双方の個体キーはツールチップとJSONに保持する。
相手の個体情報が未観測なら補わず「未観測」と表示する。

既存の同一個体・対象・表示種別・HP/SP系列内で計算したtick間隔を表示するだけで、
新たな区間を推定したり、設定攻撃ディレイやATK/DEFへ変換したりしない。
表示範囲・選択対象を切り替えると古い区間選択を解除する。
全309テスト通過。追加ログは453攻撃パケット・1,450性能観測・10クラス、解析問題0。
HP系列の比較268件、SP系列0件で、元の観測と一致することを確認した。

「MOB」タブ下側の「性能観測」でクラス別／選択個体のデータを確認する。
攻撃・被ダメージ通知数、速度通知値、最大HP通知値、左右のHPダメージ通知値合計の範囲、
同一系列内の最短tick間隔を表示する。
行を選ぶと動作ディレイと対象別の値、根拠JSONを確認できる。
「根拠パケット」は選択行の最後の観測へ移動する。
「性能観測JSON保存…」は全観測を保存する。表示中の行だけの保存ではない。

## 読み取るパケットと意味

- 008A（29バイト）、02E1（33バイト）、08C8（34バイト）の攻撃系通知。
  source/target、32bit tick、動作ディレイ、左右ダメージ、分割数、表示タイプを読む。
- 08C8のHP/SPフラグはoffset26。分割数・タイプ・左ダメージの位置は旧形式と異なる。
- 008Aの左右ダメージは符号付き16bit、新形式は符号付き32bit。
  ディレイも符号を保持する。負値を巨大な正数へ変換しない。
- アイテム取得・座る・立つ（タイプ1/2/3）と未対応の表示タイプは攻撃集計から除外する。
  これらの動作を含むパケット群なので、すべてを単純な通常攻撃の使用回数とは扱わない。
- 09FE/09FF/09FDのMOB出現／待機／移動から速度通知を保持する。
- 0977の符号付きHP/最大HP、0A36の粗い5%刻みの割合通知を保持する。

sourceとtargetのそれぞれが、その時点で同じ接続・マップ世代のMOBとして確認できるか調べる。
両方MOBなら1パケットを与ダメージ側・被ダメージ側の2観測として保存する。
attack_packet_countはこれを重複しないパケット数で数え、observationsの件数とは区別する。
未分類の攻撃を後から出現したMOBへ遡って割り当てない。

## 集計条件

個体識別は取得世代・接続・マップ世代・ActorID・出現記録・その時点のクラス。
個体内で間隔を計算した後にクラスへ集約する。
対象ID、対象の確認済み出現記録／クラス、表示タイプ、HP/SPが変われば別系列とする。
死亡・消滅後の再出現、マップ移動、再取得、変身をまたいで間隔を作らない。
tickの32bit周回に対応し、同tickは0ms間隔にしない。
逆行、半周以上の曖昧な差、不正時刻、途中取得の間隔は除外する。
問題があった観測を端点とする次の間隔も除き、その後に正常な系列へ戻る。

HPダメージ通知の範囲は、HPフラグ0で左右とも非負の通知だけについて左右値を合計する。
分割数は掛けない。負値は特殊値として別件数に残す。
SPフラグ1の通知とその間隔は別集計。不明なフラグもHPへ混ぜない。
詳細のdamage_contextsには対象・接続・マップ世代・表示タイプ等ごとの通知値と根拠を残す。

速度とHPは受信した直接値。HPが負、最大HPが非正、HPが最大HPを超える等の場合は
品質フラグを付け、最大HPの確定通知値として採用しない。元の値は根拠に残す。
HP割合も不正な値を補正しない。HP通知がなければ「未取得」で、ダメージから補完しない。

## 確定しないもの

ダメージ通知は相手の装備・耐性・スキル・表示制限等の影響を受ける。
範囲を元のATK/DEF、命中率、固定ダメージの設定値とはしない。
0ダメージ通知をすべてミスと判断しない。
動作ディレイ通知値・観測tick差は、設定された攻撃ディレイやASPDを証明するものではない。
incomingのsource_delayは攻撃した相手、target_delayは攻撃されたMOBの通知値で、両者を混ぜない。
class別の範囲は観測全体の範囲であり、完全に条件を統制した測定ではない。

transport_quality=not_verifiedを維持する。通信欠落・表示省略・再構成遅延の完全性は
証明しない。オフライン出力に含まれるTCP診断も併せて確認する。
base_atk/base_def/configured_attack_delay_msは未確定のnullのまま保存する。
生成DBの確定行や、サーバー側の性能値の自動置換は出力しない。

## 外部表示と再解析

config/auriga/display.jsonの攻撃系ルールも符号付き値・左ダメージ・分割数・SPフラグに対応した。
表示タイプ1/2/3は攻撃集計対象外の動作として表示する。文面はJSONから変更できる。
GUIの性能状態は表示定義を再読込しても変わらない。

```powershell
python -m tools.analyze_combat logs/SESSION/capture.jsonl --definitions client/PacketLength.extracted.txt --output logs/SESSION/mob-performance.json
```

WorldStore更新後にCombatStoreへ同じPacketEventとパケット番号を渡して再構築する。
GUIとCLIで同じ状態管理を使う。既存SQLite列・PacketLength・フレーミングは変更しない。
100000観測・20000個体クラス組・直近の解析問題100件を上限とする。
1パケットの2役割が上限に収まらない場合、片側だけを記録せず両側を追加停止する。
上限到達後は保存し、アプリを再起動して新しいワークスペースで取得する。

## 大量観測時の表示

攻撃間隔の根拠は1ページ最大1000区間、初期表示は系列順の最終ページとする。
前後のページで全保持区間と両端の元Packetを確認できる。過去ページは同じ範囲の更新でも維持する。
画面JSON内の長い一覧は各末尾1000件までで、省略した一覧と件数をpreview_omissionsへ表示する。
表示件数が少なくても統計のcount等は全件に基づく。性能観測JSON保存は全記録を維持する。
