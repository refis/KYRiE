# MOBの配置・再観測

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

MOBタブ下側の「配置・再観測」で、接続・取得世代・マップ世代・クラスごとの観測を確認する。
「根拠パケット」で選択行の最初の観測へ移動し、「配置観測JSON保存…」で全記録を保存できる。
CLIのtools.analyze_entitiesにもmob_spawn_observationsを追加した。
生ログのGUI読み戻し・プロジェクト再開でも同じ状態管理で再構築する。

## 保存する値

- 初回の通知種別: 09FEの出現通知、09FFの初回待機観測、09FDの初回移動観測を区別。
- 初回座標と根拠番号。後の移動で初回座標を上書きしない。
- 個体IDと出現記録、外見／クラス、観測時点のマップ、初回・最終観測時刻。
- 死亡通知、その他消滅、マップ移動、取得切替、個体・クラス変更による区間終了。
- 同じActorID・クラス・接続・マップ世代で再観測した場合の時間差と両端パケット。
- 追跡状態に同時に残っていた数のピーク。別ログ・接続・マップ世代を合算しない。

初回観測は生成された瞬間とは限らず、初回座標も固定の湧き地点とは限らない。
消滅理由1は既存デコーダーと同じ死亡通知として分類し、他の消滅とは分ける。
死亡後の同ID再観測でも、サーバーのID再利用や別個体の可能性を排除しない。
消滅後の再観測は視界への再進入の場合がある。別IDの同クラスを近さだけで対応付けない。

## 設定値との区別

configured_spawn_count、configured_respawn_msは常にnull。
server_spawn_settings_restored、configured_respawn_confirmedはfalse。
有効なmonster配置行や再出現ディレイを自動生成する機能ではない。
追跡数ピークを設定上の湧き数（amount）へ、最短再観測時間を delay1／delay2 へ変換しない。
amount・delay1・delay2・配置座標・xs/ys・event は観測自動補完の対象外であり、
[手動編集](#配置設定の手動編集)と確認チェック後の保存でのみ埋める。
通信で見えていない個体・死亡・移動が存在し得るため、真の同時存在数も保証しない。

この方針は今後の機能追加でも維持する。観測ピークや間隔の統計表示を増やしても、
それを設定湧き数・設定ディレイの確定値や自動入力の既定値にはしない（#25）。

記録終了時に消滅していない個体はend=nullで、以後の生存を保証するものではない。
配置マップは[同じフローのプレイヤー現在マップ](../observations/entity-map-context.md)を用いて補完する。
プレイヤーのマップも未取得なら不明のまま。後の移動先や個体名から過去のマップを補わない。
世代切替・別マップ・クラス変更をまたいだ間隔を作らず、途中取得や時刻逆行等の問題がある区間も時間差から除外する。
通信品質はnot_verifiedを維持し、WorldStore全体の解析問題数も保存・表示する。
個体名の解読問題がある場合も、検証できた数値フィールドは既存方針で保持する。

最大20000区間。上限到達はsaturated=trueとして以降の追加観測を停止する。
上限時は全期間を網羅した集計ではなく、保持できた範囲の観測として扱う。

## Auriga配置の編集用候補

「配置編集用候補…」から全観測の接続・取得世代・マップ世代・クラスごとの候補を保存する。
JSONはplacement_fields、requires_edit、元の集計・全個体の出現記録とログ出典を保持する。
txtはmonster宣言の列順を示す全行コメントの下書きで、不明値を?とする。
生成書式・注意文はconfig/auriga/mob_spawns.jsonで変更できる。コメント制約を外す書式は拒否する。
テキストは最大4Mi文字。出典・観測文字列の改行等はJSONエスケープして保持する。

map_nameとclass_idに観測値を置く。他の設定項目は補完しない。
マップ未観測はnullのまま。既知のマップもその表記を保持し、対象Auriga側のマップ名を確認する。
class_idは観測クラスであり、対象mob_dbとの一致を別途確認する。
初回座標はfirst_positionに根拠として残し、配置のx/yには置かない。
配置範囲xs/ys、名称mob_name、湧き数amount、delay1/delay2、死亡時イベントeventもnullとする。
追跡数ピークや再観測間隔の統計があっても amount／delay1／delay2 へコピーしない。
空イベントや範囲0を暗黙に採用せず、要編集項目に残す。
名称や初回出現通知が分かっても、元の常設湧き・召喚・イベント生成等を確定しない。
server_spawn_settings_restored=falseに加え、候補のactive_placements_generated=falseを維持する。

CLIのtools.analyze_entitiesにもauriga_spawn_candidatesとauriga_spawn_reviewを追加した。
Auriga公式の[npc.c / npc_parse_mob](https://github.com/auriga/auriga/blob/master/src/map/npc.c)
でmap,x,y,xs,ys、monster、名称、class,amount,delay1,delay2,eventの列順を2026-10-27に照合した。
手動配置編集UIと確認後の配置行付きJSON保存は、以下の手順で利用できる。

## 配置設定の手動編集

配置・再観測の行を選び「選択した配置候補の設定を編集…」を押す。
観測マップとクラス以外は空欄で始め、初回座標・追跡数ピーク・再観測間隔は自動代入しない。
編集画面上部に、開いた時点で固定した観測根拠（出現記録・追跡ピーク・初回座標・再観測間隔・
要編集列）を読み取り専用で表示する。amount／delay1／delay2／x／y への対応付けは行わず、
注意文で非対応を明示する。根拠テキストは入力欄を埋めない。
全項目を入力し「ID・マップ・全配置設定を確認し、event空欄はイベントなしと確認した」に
チェックしてJSON保存する。観測値と異なる対象DBのIDやマップを指定する場合も手動設定として残す。

- map_name: 英数字と_@.-の23文字以内。対象Aurigaで使うマップ名を確認する。
- x/y/xs/ys: 0〜1023の整数。0も明示入力が必要。対象マップの実際の範囲は別途確認する。
- mob_name: CP932で23bytes以内。改行・カンマ・スクリプト区切り等を拒否する。
- class_id: 1〜65535。対象mob_dbの存在確認は手動。
- amount: 1〜1000。この編集画面の上限であり、Auriga全体の仕様上限ではない。
- delay1/delay2: 非負整数のms。それぞれと合計を符号付き32bit以内に制限する。
- event: 空欄を明示的なイベントなしとするか、NPC名::OnラベルをASCIIの76文字以内で指定する。
  NPC・ラベルの実在やイベント起因条件を推定しない。

JSONのplacement_rowに配置行、placement_fieldsに設定、observationに編集前の候補と個体別根拠、
source_sessionsにログ出典を保存する。setting_origin=manual_reviewで観測と区別する。
active_placement_generated=trueは確認済み設定から行を生成したことを示し、元の湧き設定の復元ではない。
元の観測ストアのserver_spawn_settings_restored=false、未確定設定nullは変更しない。
注意文・配置書式はconfig/auriga/mob_spawn_configured.json。列順と区切りを壊す書式は拒否する。
保存は最大8MiB。元ログ・生成書式への上書きは拒否する。
DB/NPCファイルへの自動書込は行わない。生成した配置行は検証環境で読込確認する。
手動設定はプロジェクトへ自動保存されないため、設定JSONを別途保存する。

### 保存した設定の再編集とテキスト出力（2026-10-28）

同じ配置観測行から編集画面を開き「保存した設定JSONを読み込む…」で再開できる。
観測候補・個体別根拠・出典・確認フラグ・配置行・現在の生成書式を照合する。
異なる観測や出典、変更された配置行、重複JSONキー、非有限数、8MiB超過は拒否する。
不正な読込では入力内容を変更しない。読込が成功しても確認チェックは外すので、
編集内容を確認して再チェックしてから保存する。

「確認済み配置行を根拠付きテキスト保存…」は注意文と全観測・出典のJSONコメントに続けて、
有効なmonster配置行を1行だけ出力する。出典などに含む改行はエスケープし、追加命令にしない。
未確認の入力は出力しない。設定JSONと同様、元ログ・生成書式への上書きを拒否する。
この出力は手動確認した設定であり、湧き数・湧き時間・位置を観測から確定した結果ではない。
Auriga本体での配置読込・実行試験は別途必要。

編集画面は開いた時点の観測候補・出典をコピーして保持する。
上部の観測根拠パネルも同じ固定コピーから生成し、入力変更や設定JSON読込では書き換えて設定欄へ流し込まない。
追加受信があっても、編集中の根拠へ自動的に混ぜない。最新の観測を採用する場合は編集画面を開き直す。
入力項目を変更すると確認チェックとプレビューを解除する。
確認後の「確認済み配置行と根拠を表示」で、保存前にテキスト全体を確認できる。
JSON・テキストとも、一時ファイルへの書込が完了してから保存先を置換する。
保存失敗時は既存ファイルを保持し、一時ファイルを削除する。
