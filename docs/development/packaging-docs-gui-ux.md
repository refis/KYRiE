# 文書分割・GUIユーザビリティの検討（EXE化なし）

[資料一覧](../README.md) · [開発計画](development-roadmap.md) · [NOTICE](../../NOTICE)

日付: 2026-11-06（日本時間）。**EXE化およびEXE配布は行わない**（利用者方針）。
起動の正本はソース＋venv（`python main.py`）と private ソースZIPのみ。
次の着手は [development-roadmap.md](development-roadmap.md#次の着手単位) を参照。

## 現状（点検結果）

| 領域 | 現状 | 主な制約 |
|------|------|----------|
| 起動 | `python main.py`（venv＋`requirements-lock.txt`） | Windows＋Npcap＋権限が実取得の前提 |
| 配布物 | private ソースZIP（`tools.build_snapshot`）のみ | EXE配布なし。logs／DB／client EXE／`.reference` 除外 |
| 文書 | `docs/guide`＝操作、`npc`/`mob`/`capture`＝契約＋操作混在、`development`＝方針 | 目次は読者軸を強化済み。操作ガイドに古い検証履歴が残る箇所あり |
| GUI | 作業／設定・診断／出力／ヘルプ＋用途別タブ | P2-3（タブ初期プリセット）は任意 |

## 1. 実行形式（確定方針）

**PyInstaller／Nuitka 等による EXE 化、および EXE の配布・試験ビルドは実施しない。**
Npcap・管理者権限・表示JSON編集・辞書更新はソース起動のまま扱う。
ソーススナップショットは EXE 配布や公開リリースではない（[releases/README](../releases/README.md)）。

## 2. 利用者向け／開発向けドキュメントの分割

### 結論

**いきなりディレクトリを全面移動しない。** 目次の読者軸分割は着手済み（[docs/README.md](../README.md)）。
続いて操作ガイドから「検証履歴」を分離する。仕様契約（npc／mob／capture）は共有正本のまま。

### 読者軸

| 入口 | 含むもの | 含めないもの |
|------|----------|--------------|
| 利用者 | 導入、GUI操作、再解析、採取チェックリスト、限界・NOTICE | テスト件数履歴、プロファイル計測の詳細、MARiA差分表全文 |
| 仕様契約 | 観測意味・生成境界・未対応一覧 | 「いつ何件通したか」の時系列 |
| 開発 | roadmap、progress-notes、working-agreement、テスト方針、hook設計 | 日常操作手順の重複 |

### 段階

- **A（済）**: docs/README を利用者／仕様契約／開発の3入口に再編。
- **B（済）**: `gui-workspace.md` から古い実装予定・検証件数段を除去し操作説明へ純化。
- **C（任意）**: `docs/user/` 等への物理移動はリンク一括更新とセット。

## 3. GUI ユーザビリティ

### 結論

次は **発見性** と **診断への導線**。利用感が変わるため、**v0.0.10 スナップショット保存後**に着手する。
簡易モードや大規模レイアウト改修は後段。

### 段階（P2）

- **P2-1（済）**: ヘルプ／About、主要 toolTip、状態ラベルクリックで診断
- **P2-2（済）**: F5／F8／Ctrl+Shift+O、開始前チェックリスト（設定は黙って変えない）
- **P2-3（任意）**: 観測中心／復元中心のタブ初期プリセット

対象外: 未観測条件の自動補完、取得契約の緩和、推測による命令増加、EXE化。

## 推奨の着手順

1. **v0.0.10 ソーススナップショット**で現状の利用感を保存する（済）。
2. 操作ガイド純化と GUI P2-1／P2-2（済）。
3. 必要なら P2-3。物理 docs 大移動は明示指示の後。

## 非目標

- EXE化・EXE配布・公開ストア配布。
- Linux CI offscreen 成功を Windows／Npcap 実機の代替にしない。
- 「全MARiA互換」を完了条件にしない。
