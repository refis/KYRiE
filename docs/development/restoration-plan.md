# 開発目的と復元処理の優先順位

[資料一覧へ](../README.md) · [プロジェクトREADME](../../README.md)

2026-10-27時点の残作業、MARiAとの差分、実装順・完了条件・最適化は
[今後の開発計画](development-roadmap.md)を参照。この文書は基本方針を保持する。

## 主目的

Auriga方式のNPCスクリプトとMOB解析結果の復元を中心とする。
MARiAの情報保持・スクリプト出力・MOBスキル整理を機能上の基準にする。
rAthena向け出力は低優先度の独立した表示プロファイルとして扱う。
HTTP通信はゲーム解析の対象にしない。

単一パケットの文字列表示は復元の基礎であり、最終的なNPCコード生成器とは分ける。

## 処理構成

1. TCPから完全なPacketEventを生成する。送受信・接続世代を維持する。
2. バージョンに対応するデコーダーで意味イベントを作る。
3. マップ、NPC/MOB個体、プレイヤー、会話、戦闘の状態を更新する。
4. 観測履歴から会話分岐・時間関係・スキル統計を組み立てる。
5. 復元用の中間表現からAurigaコードやMOB集計を外部テンプレートで出力する。

表示文を解析し直して状態を作らない。表示書式を変更しても解析結果を変えない。
中間表現と観測データを保存し、同じログから生成結果を再現できるようにする。
生成要素には根拠となるパケット・接続世代・時刻を持たせる。

## 実装順

### 1. NPC/MOB情報保持と一覧

MARiAのNPC/MOB辞書に相当する状態管理を移植する。
出現・待機・移動・消滅・名前応答から、個体ID、種別、外見/クラス、名前、マップ、
座標、向き、速度、表示オプションを保持する。接続世代・マップ移動・再出現を区別する。
まずNPC一覧、MOB一覧と観測根拠をGUI・ファイルに出力する。

### 2. Auriga会話コード生成

SENDのNPC指定、選択肢応答、次へ、入力、終了と、RECVのmes/next/menu/cutin等を
関連付け、会話セッションごとのコードを生成する。
NPC名・配置・外見を一覧情報から解決する。観測した分岐を保持し、未選択の分岐や
起因・サーバー側の変数名・条件式・クエスト状態の判定は生成対象外とする。
矛盾観測と入力後の続きはインデント付き{}で併記し、入力値をコメントに残す。
複数選択肢はswitch、単一／全応答同一はラベルなしmenuを基本とする。
MARiAが持つ演出・移動・ワープ・クエスト等の出力を順次この中間表現へ移す。

### 3. タイマー型イベント

会話開始・選択・マップ到着・MOB出現などの基準イベントと、その後の演出や台詞の
相対時刻を観測する。入力待ち区間と入力なしで進む区間を分け、複数回の記録で
再現する時間関係を集計する。表示用タイムスタンプとタイマーコード候補は別に持つ。

通信で観測した待ち時間は、元コードのOnTimer値、イベントラベル名、sleep系命令、
サーバーの処理遅延を一意に決める情報ではない。まず根拠付きタイムラインと候補を
出力し、確認された条件でAurigaのタイマー／待機コードへ変換する。
パケット欠落・途中取得・時刻逆行・大きなジッターがある区間は推定の品質に反映する。

### 4. MOB性能・スキル解析整理

MARiAのモンスター配置・再出現観測、スキル表出力を移植する。
個体単位でスキル開始・発動・詠唱キャンセル・攻撃・移動・消滅を追い、
スキルID/レベル、対象、詠唱時間、観測再使用間隔、命中回数・分割数・効果値を保持する。
個体ごとの時系列を計算してからクラス別に集計し、複数個体の交互使用を短い再使用時間と
誤認しない。スキル名・状態名・ユニット名は外部辞書に分離する。

表示HP・移動速度・攻撃ディレイなどの直接値と、戦闘結果から推定する性能値を分ける。
元のATK/DEFやAI使用条件・発動確率は、プレイヤー装備・耐性等の条件なしには確定しない。
最短観測間隔は設定された再使用ディレイそのものと断定しない。
不明なレベルをダメージ等の値で自動置換せず、未知値と候補を残す。
Aurigaのmob_skill_db形式は公式doc/db_ref.txtと照合して出力する。

### 5. rAthenaプロファイル

Auriga側の意味イベントと中間表現を共有し、出力だけ分離する。
受信ログ用 `config/rathena/display.json` はAurigaと同IDの表示定義を持つ。
Auriga固有のインスタンス命令をrAthena対応済みとして出力しない。
コード生成用プロファイル（dialogue / shops / mob_* / status_ids 等）のrAthena版と、
それらを切り替える本体改変は未着手。

## 今回完了した土台

- 初期HTTP開始行／HTTP/2 prefaceの認識による両方向PASS。
- Aurigaの既定表示: `config/auriga/display.json`（既存73 IDを含む93 ID）。
- rAthenaの受信ログ表示: `config/rathena/display.json`（Aurigaと同ID。生成用JSONは未分離）。
- `config/receive_display.json` は既存設定の互換用に残す。
- 旧ファイルやカスタム設定はGUIのBrowseで引き続き選択できる。
- 第1段階のNPC/MOB状態保持・一覧・観測JSON保存・ログ再構築を追加した。
  対応レイアウトと観測根拠は[エンティティ観測ガイド](../observations/entity-observations.md)を参照。

会話用の中間表現・観測経路のAuriga本文候補・GUI保存を追加した。
対応範囲は[会話復元ガイド](../npc/dialogue-restoration.md)を参照。
会話の入力待ち／応答／入力なし区間のタイムライン・反復比較を追加した。
NPC/MOB初回出現・移動と所持品／Zenyの観測ログ、およびGUI基本データを追加した。
範囲は[基本データガイド](../observations/player-observations.md)を参照。
[時間経過ガイド](../npc/dialogue-timing.md)を参照。
MOBスキルの個体別通知・間隔・クラス別集計を追加した。[MOBスキルガイド](../mob/mob-skills.md)を参照。
攻撃・被ダメージ通知、速度、HP、個体内の攻撃通知間隔の整理とGUIを追加した。
[MOB性能ガイド](../mob/mob-performance.md)を参照。元のATK/DEFや設定ディレイは未推定。
識別できるNPCの観測経路をまとめ、不一致を編集用ブロックで併記する候補生成を追加した。
[分岐統合ガイド](../npc/dialogue-merging.md)を参照。
会話外のイベント時間解析、タイマー命令生成、MOBのAI条件・設定ディレイ復元は今後の実装対象。
会話中の同一NPCを対象とするエモーション・効果音の本文候補化を追加した。
入力待ち中の並行演出を本文とは別列で保持し、反復比較・時間経過表示を追加した。
会話外の演出も対象・接続・時刻付きで保持するが、基準操作が不明なため反復比較は未対応。
NPC会話の起因・変数・隠れた条件式の判定は生成対象外。
配置が揃ったNPCの[配置付き編集用ファイル](../npc/npc-file-export.md)出力も追加した。
HTTPのPASSだけをコード復元機能の完成とは扱わない。
